# LifeStory Studio 人类使用手册

更新：2026-11-05。本手册帮助你和 Codex 协作开发项目；软件本身的使用说明以后按需要另行编写。

## 你需要做什么

你只需用日常语言告诉 Codex 想做什么、审阅重要方案，并在需要时反馈使用体验。Codex 负责梳理需求、实施、按风险验证和维护文档；涉及产品方向、隐私、费用等真正需要决定的事项，会向你说明。

不需要亲自维护任务表或理解所有技术文档。完成一项工作时，Codex 应说明改了什么、实际检查了什么、哪些还没验证；不能把代码完成、自动化通过和用户验收当成同一件事。

## 日常看哪里

| 你想了解什么 | 查看 |
|---|---|
| 产品要做什么、已确认什么、还有什么待决定 | [产品与决策](PRODUCT.md) |
| 现在做到哪里、下一步是什么 | [项目跟进](STATUS.md) |
| 当前版本的工作、验收方式与状态 | [验证与验收](VERIFICATION.md) |
| 如何启动和开发 | [开发说明](DEVELOPMENT.md) |

需要了解某项功能的具体行为时，看 [日记](features/DIARY.md)、[聊天](features/CHAT.md)或[模型设置](features/MODEL_SETTINGS.md)。[架构总览](ARCHITECTURE.md)、`architecture/`、`process/` 和 `research/` 主要供 Codex 开发、验证和追溯依据时查阅，不需要每次都读。

编号只是方便关联：`REQ` 是产品需求，`TASK` 是工作项，`DEC` 是重要决定，`LIB` 是资料库模块的子任务。项目进度不按编号大小判断。

## 现在项目在哪里

当前开发版本为 `0.1.0`，尚未正式发布。资料库和 AI/对话已完成本轮交付；用户已确认约定的 Codex、API、日记创建与补充，以及 Windows 主链路，未逐项验证的专项仍保留。

当前推进文案审查：需求与前端 UI/UX 已确认，真实审查链路已接入，用户报告桌面验收用例 1～8 全部通过；其他平台、服务组合及未列专项仍待验证。写作练习和个人风格档案按用户要求暂缓；最新进展以 [STATUS](STATUS.md) 为准。

## 怎样交代工作

直接描述目标、遇到的问题或期望，例如：

- “日记保存后重开内容不对，帮我排查并修复。”
- “整理文案审查的完整流程和验收条件，先给我看方案。”
- “看看当前有哪些事项还没验证。”
- “从 develop 开分支完成这项工作，并创建 PR。”

需要你验收时，Codex 应提供可操作的步骤，并区分你的反馈与自动化结果。UI 视觉实机检查按你此前的要求由你进行；Codex 不用截图或测试结果代替你的确认。测试使用合成资料，不需要把真实日记或密钥发到聊天中。

## 版本、分支和发布

当前使用 `主版本.次版本.修订版本` 格式。`0.1.0` 是开发版本，不表示已经发行；功能里程碑和需要单独交付的修复可分别递增次版本或修订版本。升级哪一位、何时进入 `1.0.0` 由你明确决定，不因普通任务或文档修改自动升级。版本配置的同步由 Codex 处理；候选包可由现有 CI 生成，但实际候选打包与安装仍待验证。

日常通常从 `develop` 创建任务分支，通过 PR 回到 `develop`；准备版本候选时使用 `release/<版本>`，`main` 是正式基线。提交、推送、创建 PR、合并及发布按你对当前任务的授权执行；合并 PR 不等于对外发布。提交和 PR 的自然语言说明使用中文。完整规则见 [Git 流程](process/GIT_WORKFLOW.md)。

每次工作完成后查看 [验证与验收](VERIFICATION.md)：前部是当前工作及待验收事项，后部保留已交付证据。它按开发版本维护，同版本的任务分支继承并更新相关内容，不能清空其他待办。进入下一版本前，先确保上一版本记录和必要证据已提交并可追溯。

## 测试与隐私

测试按风险选择：保存恢复、迁移、权限、引用、冲突和异步取消等高风险行为需要自动化保护；普通文案和装饰样式不机械新增测试。`src/components/ui/` 组件库不编写、维护或运行组件测试，业务交互仍按风险验证。完整规则见 [测试策略](process/TESTING_POLICY.md)。

应用以本地保存为基础，不做云同步；AI 任务只使用你明确选定的资料。API Key 按已确认方案明文保存在本机应用私有配置中，不加入应用备份或导出。真实服务收到资料后的处理取决于该服务；使用前可核对服务目标与资料范围。

## 换聊天后继续

在可以访问项目文件的新聊天里，直接说：

> 阅读项目规则和当前进度，先告诉我现在做到哪里，再继续已授权的工作。

Codex 应读取 [AGENTS.md](../AGENTS.md)、[项目跟进](STATUS.md)和相关资料，并以你最新的明确指示为准。文档不会自动安排定时任务或在没有会话时继续开发。
