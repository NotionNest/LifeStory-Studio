# Git 与远程协作流程

2026-10-16 用户确认。仓库 [NotionNest/LifeStory-Studio](https://github.com/NotionNest/LifeStory-Studio) 已按用户要求改为公开。

## 分支与流转

- `develop`：日常集成基线。任务从这里创建 `feat/*`、`fix/*`、`docs/*`、`chore/*` 或 Codex 的 `codex/*`，通过 PR 回到 develop。
- `release/<版本>`：从 develop 切出的版本候选，只接收 fix/chore 修复和发布准备；不接收新功能。版本未确定时不创建分支。
- `main`：正式基线，接收 release 候选或从 main 出发的 `hotfix/*`。本次 hotfix/git-workflow 是流程迁移的一次性基础设施引导。
- 正式合入后 main 通过 PR 回合 develop；紧急修复也回合仍维护的 release。

任务 PR 通常 squash；release→main、main→develop、main→release 使用 merge commit，保留共同祖先。仓库允许 merge/squash，关闭 rebase merge 和自动合并。关闭自动删除来源分支，避免回流时误删 main；确认没有依赖后手动删除短期分支。不得强推共享分支、覆盖未提交工作或机械清理旧分支。

## 日常操作

1. 检查工作区并保护已有修改，再同步对应基线。
2. 按任务分支实现、按测试边界验证，更新规格与 STATUS。
3. 提交前检查文件与 staged diff；不提交密钥、私人资料、资料库、构建产物。
4. 使用 feat/fix/docs/chore 等明确提交说明，不使用 CI 跳过标记。
5. 按当前任务授权推送并创建 PR；检查 CI Gate 和实际修改后，按授权合并。合并不等于发布授权。

## PR 与提交语言

2026-10-19 用户要求：后续 PR 标题、PR 正文、commit 标题与正文统一使用中文说明。必要的类型前缀、scope、分支名、文件路径、命令、API 和代码标识保留英文原文。

示例：

```text
fix(library): 修复切换记录时的保存边界

切换期间保持旧记录只读，保存最新内容后再进入目标。
验证：关键交互测试通过；Windows 实机尚未验收。
```

简单提交只写中文标题即可，不强制增加正文。PR 正文按模板说明问题、修改后的行为、验证及兼容性影响。Squash/merge 时核对最终提交消息，用中文替换自动生成的英文说明；保留必要的 PR 编号与来源信息。无需改写历史提交。

## Actions 分层

| 时机 | 行为 |
|---|---|
| 指向 develop/release 的 PR | 路由/范围门禁始终运行；按下列改动内容选择轻量任务 |
| 普通说明文档 | 仅策略与 CI Gate，不安装应用依赖 |
| 前端代码、前端依赖/构建配置 | Ubuntu：严格依赖安装、类型检查、生产前端构建、关键交互；不运行 Rust 或双平台桌面编译 |
| Rust、存储、Tauri 配置、数据契约 | macOS 单平台：Rust 格式、真实存储测试、Clippy；不安装 npm 依赖，不额外运行桌面构建 |
| 图片验证工具 | Ubuntu 单平台：工具格式、测试、Clippy |
| 共享工作流/工具链或未知非文档路径 | 上述轻量任务全部检查，不自动运行双平台桌面编译 |
| release push / 手动完整检查 | 完整 macOS/Windows Rust 测试、Clippy、桌面编译及双平台图片验证；前端通用检查一次。release 候选另外生成安装包 |
| hotfix→main | 完整双平台检查，避免紧急修复直接进入正式基线而没有跨平台验证 |
| release→main | 必须有相同提交、来源分支、与合并树一致的最新成功候选；只核验证据，不重复前端/Rust/图片/桌面编译 |
| main/develop 合并后 | 不再重复构建；PR 门禁由服务器强制执行 |

候选版本由一致的 package/Tauri/Cargo 基础版本生成 `<版本>-rc.<运行号>`，构建机内同步锁文件；使用 Preview 名称和 `.preview` 应用标识，隔离稳定版数据。未签名测试产物，不自动创建 GitHub Release 或正式标签。候选构建配置已实现，真实候选打包与安装尚待首次版本确定后验证。正式签名、公证、Windows 安装升级、备份恢复和发布授权仍是发布验收条件；当前没有自动正式发布通道。

只修改 PR 标题/说明时，不取消已有验证，也不重跑昂贵任务。该次事件使用独立并发组，CI Gate 轻量核实同一 PR、同一来源提交、同一目标分支及基线的最新完整验证；验证仍在运行就等待其结束（最多 65 分钟），未成功或缺少证据不能放行。完整运行名称固定保存当时的目标分支和基线 SHA，避免误信 GitHub API 中会随 PR 改动的目标信息。只有这项校验通过才给出新门禁成功；不能以 skipped 或无条件成功覆盖旧结果。改目标分支会完整重新判断检查范围。

若完整验证或轻量验证因失败、取消或 API 错误失败，先处理原失败，再在原 PR 重跑对应失败任务；仅编辑说明不能把失败改成成功。

候选可以由 push 或手动 Release candidate 产生。若候选尚未成功而 Checks 先失败，完成候选后在原 PR 的 Checks 中重新运行失败任务；不能以普通编译代替安装包证据。目标合并树有变化时，先通过 PR 将 main 同步到 release，再构建新候选。

同一 PR 的新提交取消过期验证。Rust 检查和桌面/候选构建都使用 --locked；完整桌面任务已包含 Rust 检查，不再叠加单平台 Rust 任务；候选仅允许自身版本与锁文件中的应用版本同步修改，不允许无关依赖重新解析。依赖缓存使用固定提交的 Swatinem/rust-cache v2.9.2，排除工作区自身产物和增量文件；CI 关闭开发/测试调试符号。不为建立共享缓存新增一次完整构建。必要任务失败、取消或意外跳过，以及检查范围输出缺失/非法，都会导致 CI Gate 失败。不以覆盖率、普通标点或装饰样式用例增加检查量。CI 通过不代表双平台实机交互或发布验收通过。

## 服务端保护

2026-10-16 用户明确要求公开仓库以启用保护，已从 private 改为 public。此前私有仓库的套餐限制属于历史状态，不再代表当前配置。

已启用规则集 [Integration branches](https://github.com/NotionNest/LifeStory-Studio/rules/25221010)，状态 active，匹配 main、develop、release/*：

- 更新必须经 PR，必须解决评审讨论；审核批准人数为 0，不要求单人项目自我审批。
- 必须通过 GitHub Actions（应用 ID 15368）提供的 CI Gate，并要求 PR 基于最新目标分支验证。
- 禁止强推和删除匹配分支；没有配置绕过角色，管理员也不在绕过名单中。
- 允许 merge 和 squash，关闭 rebase merge；具体流转的合并方式继续遵守本文分支约定。
- 新建版本分支可先创建，再由候选工作流验证；尚未确定版本，不因此创建 release 分支。

已通过规则查询接口核实 main 和 develop 均实际应用上述保护；不以破坏性推送试验规则。公开仓库没有改变资料本地保存和测试使用合成数据的要求。代码公开不等于已经选择开源许可证，也不等于产品发布。
