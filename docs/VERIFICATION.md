## 版本验收约定

每项变更记录所属版本、关联 REQ/TASK、功能或问题、实际运行的检查及结果、用户验收和未覆盖范围；必要时记录分支或 PR 便于追溯。未运行写“未运行”，不以自动化代替实机或用户确认。测试结果注明对应代码基线、平台及时间；不能把旧结果冒充新提交通过。

`0.1.0` 期间，普通任务分支继承当前版本记录并更新相关项目；合回 `develop` 时合并结果和未完成事项，不清空其他待办。分支上的记录需要提交并进入目标分支，才能被后续从目标分支创建的分支继承；未提交或未合并成果不得覆盖。

进入下一开发版本前，确认上一版本验收记录及必要证据已提交、能由版本提交或标签追溯；保留未提交和未合并成果，再更新本页。未来 `release/<版本>` 的记录作为对应候选的验收依据；版本递增规则见 [Git 流程](process/GIT_WORKFLOW.md)。此前 development 内的性能原始数据及脚本已按用户要求删除，不再提供对应复现材料。
