# 图片支持矩阵与验证

日期：2026-10-15。范围：LIB-01 Rust 解码验证；正式导入、系统文件选择/拖入/粘贴与编辑器预览尚未接入。

## 支持契约

采用 image 0.25.10 原生 Rust 解码，功能仅启用 PNG/JPEG/WebP，按实际字节签名识别，不信任扩展名。静态 PNG、JPEG 和 WebP 纳入正式导入支持范围；APNG/动画 WebP 明确拒绝，GIF、HEIC、SVG、TIFF 等本轮不纳入支持，不自动转码。保留原图，不静默压缩。

单张编码文件上限 25 MiB（26,214,400 字节），解码尺寸上限 40,000,000 像素、任一边不超过 16,384 像素。解码配置 256 MiB 分配预算，此预算并非整个进程内存硬上限。多个图片串行验证，避免批量解码叠加内存；正式导入需在读取前检查文件大小，并以有界读取应对文件读取中变大。不得先完整读取任意大文件再只检查长度。

该限制是明确拒绝策略，不在失败后降采样或替换解码器。显示方向、色彩配置、缩略图和元数据隐私在 LIB-05 中验证；此处不宣称已完成所有照片显示兼容性。

## 验证证据

独立验证程序： [tools/image-validation](../../tools/image-validation/README.md)，有单独锁文件及合成样本。macOS 本机 2 项用例与 Clippy 通过；Windows 与 macOS CI 结果待执行后更新。

覆盖：三种静态格式的签名识别/完整解码、截断输入、未知数据、APNG/动画 WebP 拒绝、字节上限与尺寸上限拒绝。像素乘积使用 u64 防溢出。该验证是格式与规则验证，不等于系统粘贴/拖入或正式附件保存链路已验证。

依据：经 Context7 检索 image 官方文档，并由已锁版本编译核实 API。[image 0.25.10](https://docs.rs/image/0.25.10/image/)、[Limits](https://docs.rs/image/0.25.10/image/struct.Limits.html)。Limits 的分配限制为尽力约束，严格维度检查另行执行。
