# 文案审查：基础校对

状态：需求及前端 UI/UX 已经用户体验确认；运行时模拟流程已清理，真实 AI 审查及完整功能尚未实施。关联 REQ-04，涉及 REQ-01/11/12。更新：2026-11-06。

## 目标与范围

用户希望校对文字中的错别字、标点、语句不通顺、重复和冗长，尽量减少对作者原意、事实和表达习惯的影响。目标是帮助作者发现并修正具体问题，不以写作教练、文章打分、结构分析或改写个人风格为本次目标。以后可以提出新想法，不预先将其纳入本次范围。

用户参考 [Hemingway Editor](https://hemingwayapp.com/)；其[问题标记说明](https://4.hemingwayapp.com/help/docs/highlighted-issues)可为定位和处理建议提供参考。英文可读性等级、长句或被动语态等规则不直接作为中文错误标准。

### 审查内容

| 类型 | 关注点 | 最小干预原则 |
|---|---|---|
| 错别字 | 疑似错字、误用词、缺字、多字及输入残留 | 人名、地名、专有名词、方言及有意用法不凭空断定为错误；不确定时提示核对。 |
| 标点 | 明显误用、缺失或多余的标点，以及括号、引号疑似不配对 | 不为了统一风格改动有表达目的的停顿或标点。 |
| 语句不通顺 | 明显影响理解的语序、成分、指代、搭配、用词或句子衔接问题 | 优先局部调整；含义不明时提出疑问，不猜测事实。 |
| 重复 | 同一句或相邻语境中无意重复的词句、信息 | 不删除有强调、节奏或叙事目的的重复。 |
| 冗长 | 不必要的累赘表达影响理解 | 保留有意义的细节、语气和情感；长度本身不是问题。 |
| 称谓或数字不一致 | 同一对象的称谓、数字前后疑似不一致 | 仅提示核对，不推断事实或自动决定哪一处正确。 |

## 流程与行为：用户已确认

2026-11-06：用户要求在文案审查侧栏顶部提供撤销与重做。当前实现沿用日记正文编辑器历史，采纳建议作为独立的撤销步骤；用户进一步要求撤销采纳时恢复对应建议和标记，重做时再次应用，其他未受影响建议继续保留。审查状态仅保留在当前面板会话中。

1. 仅在已有日记内主动发起审查，审查整篇正文，不支持选中片段审查，也不审查独立文案；使用现有 AI 接入并提供可见的模型选择。
2. 审查结果对应发起时的文本快照，标出具体原文。点击标记查看类型、简短原因和可行修改；不确定处以“建议核对”呈现，不能伪装为确定错误。无问题时明确显示未发现建议，不承诺文本完全无误。
3. 作者可忽略建议、自己修改；适合替换的建议展示原文与修改后内容，由作者逐条明确采用。复杂或含义不明的问题可以只提示，不强制生成替换文本。仅逐条处理，不提供批量操作。
4. 明确采用后才修改对应文字；变更走现有编辑、自动保存、撤销与历史保护流程，不修改其他文字或图片。对于原文已经变化、位置不唯一或无法可靠定位的建议，不盲目替换；保留建议供查看，并提示重新审查或手动修改。
5. 若使用 AI，发起前明确本次发送的文本范围及目标服务，沿用用户选择的接入方式；不默认发送图片或其他记录，不自动切换服务。使用现有 AI 接入；结果不保存、不重开，用户可主动重新审查。

## 边界与状态：用户已确认

- 空白、仅图片或无可审查文字时说明原因，不发起请求；长文超过实际服务能力时明确说明，不静默截断或声称已审查全文。
- 生成中可停止；取消、失败或服务不可用时保留正文，提示真实状态，用户决定是否重试。不得将部分结果宣称为完整审查。
- 重复原文、跨段落、富文本格式和图片附近的建议必须可靠定位；无法可靠匹配时不提供自动替换。对重叠建议，采用其中一项后重新核验其余建议。
- 切换记录、删除、重新打开或应用退出时，审查过程及结果直接丢弃并失效；迟到结果不得显示或写入。任何情况下不得越过现有保存、冲突和离开保护。
- 不因追求建议数量而编造问题；不可擅自增删事实、推断经历、套用风格或改变作者语气。自动建议可能有误，作者保留最终决定权。

## 验收场景：用户已确认

| 场景 | 预期 | 验证方式 |
|---|---|---|
| 基础校对 | 合成文本涵盖已确认的校对类型及补充情形时，能查看对应原文、类别、简短原因和适用的处理建议；类别与内容由人工评审，不要求每次模型输出完全相同。 | 合成样例与人工评审，按实际模型记录配置。 |
| 保留表达 | 对有意重复、口语、专名及具有叙事作用的细节，不以统一风格为由强行修改；存疑时允许不修改。 | 合成正反例及人工评审。 |
| 用户控制 | 未采用建议前正文不变；逐条采用只修改对应内容，编辑后可撤销，保存与历史遵循现有规则。 | 关键交互及存储自动化，桌面实机检查。 |
| 位置和冲突 | 原文已改、重复内容定位不唯一或建议重叠时，不得错误替换或覆盖新的编辑。 | 自动化覆盖版本、定位与冲突边界。 |
| 请求和异常 | 范围与服务清晰；空正文不发送，取消、失败、超限或返回不完整时不损坏正文，也不伪称完整成功。 | 合成服务与关键交互自动化；不自动调用付费服务。 |
| 图片和格式 | 只修改目标文字，图片、相邻内容及其有效关系不丢失。 | 使用合成富文本和图片的集成验证。 |

## 已确认的界面与交互

2026-11-06 用户确认前端 UI/UX 体验阶段完成，后续真实实现须与已确认界面对齐：

- 日记右侧栏统一承载审查与聊天；顶部图标互斥切换和关闭，面板无独立关闭按钮。
- 未开始时中央提供审查入口；审查进行中可停止，完成后顶部提供重新审查、模型选择以及编辑器撤销、重做。交互须清楚标识所选服务、模型与发送范围，不因精简界面省略已确认的隐私边界。
- 建议按类别以不同颜色及线型在原文和列表中对应标记；点击标记或卡片联动，卡片顶部图标提供定位、忽略及可用时逐条采纳。
- 正文无关处编辑不应使所有建议失效；逐条重新核验，无法可靠定位的建议保留并显示“需重新核对”，不可定位或采纳，仍可忽略。采纳后其余建议保留，撤销或重做时同步对应建议及标记。
- 未发现建议、全部处理、失败及停止分别呈现；失败可主动重试。避免冗余说明和无必要的状态文案。
