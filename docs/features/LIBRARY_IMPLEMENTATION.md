# LIB-01：资料库详细实施设计

日期：2026-10-15。状态：LIB-01 契约与图片能力验证已完成；LIB-02 文字记录已实现，验证见交付记录。产品依据：[已确认页面流程与任务拆解](LIBRARY_REVIEW.md)。本文件为实施契约，不新增产品范围；实际 API 语法及依赖接入在编码时按项目规则检索当前文档。

## 数据职责

| 数据 | 身份与写入规则 |
|---|---|
| 资料条目 | 稳定 ID、类型（文字/对话/整理稿）、可选标题、记录日期、创建时区、绝对创建/修改时刻、当前版本及回收站状态 |
| 内容版本 | 不可变 ID、条目 ID、结构化编辑文档、检索文本、创建时刻、重要标记；正文节点具有稳定段落身份 |
| 对话消息 | 会话 ID、顺序、角色、消息内容与附件关联；原始用户消息与模型回应明确区分，追加幂等 |
| 来源关系 | 稳定来源版本及片段；正文中的图片引用使用附件 ID，不保存任意本地路径 |
| 恢复草稿 | 条目 ID、base revision、编辑序号、内容及更新时间；与不可变正式版本分离，不参与日常检索 |
| 图片对象与关联 | 对象摘要、受管理相对路径、类型与尺寸；记录版本/消息的关联独立于物理文件，当前关系随正文同步，历史/消息/草稿关系保护对象；无图片独立回收期限 |
| 标签 | 稳定标签 ID、显示名及归一键；条目多对多关联，移除标签不删除条目 |
| 清理状态 | 删除时刻、到期时刻与待清理对象；物理文件删除可在事务提交后继续执行，不把失败误报为已彻底清理 |

迁移在既有数据库工作线程中执行，保留事务回滚及更高 schema 拒绝写入。结构化文档是编辑来源，检索文本由同一保存操作生成；不使用搜索索引反向恢复正文。

## 保存与恢复契约

保存输入包含条目 ID、base revision、幂等请求 ID、客户端编辑序号、元数据和结构化内容。数据库事务校验会话、当前检查点与附件关联，写入最新当前内容并更新索引与必要关系；达到检查点条件时才新增不可变版本，返回检查点身份和已提交编辑序号。

界面只将已成功保存的对应编辑序号标为已保存。保存期间有新输入时仍保留待保存状态；单条记录串行提交，不能让旧回执覆盖新编辑。版本不匹配返回冲突与当前版本身份，不自动重写或合并正文。

2026-10-16 执行参数：单一写入链路，停止输入 800 毫秒提交；持续输入最长 2 秒提交一次；快捷键立即触发。中文输入法组合期间不序列化半成品，结束组合后继续调度。这些参数属于实现起点，按实际输入体验验证，不构成每个按键写入版本的要求。

当前内容持久化不等于创建历史版本。历史检查点保持不可变，不就地覆盖；不变内容不创建重复版本。历史列表按重新进入编辑形成的快照展示，恢复操作额外生成恢复前与恢复结果快照；底层版本保持可引用。普通历史从版本创建时刻起保留 90×24 小时；清理时重新检查当前指针、重要标记与引用保护。

旧版遗留恢复草稿按原流程预览处理；新编辑不再调用 recovery_write，当前内容在 records 的 working_document/working_text/pending_date 中原子持久化，与不可变历史检查点分开。通常在重新进入编辑时固定上一轮内容；2026-10-20 图片删除前增加必要历史保护，其他写作不额外生成历史；新建空白及未变内容不新增。完整快照含正文、标题、日期和标签。当前并发身份为 contentVersion，历史身份为 checkpointId；二者不混用，打开及保存核验当前内容版本。后续来源选材固化属于相应模块，不提前添加写作中历史触发器。空日期保存为待补充，列表沿用最后有效归档日期。每条记录只保留最新请求回执，旧序号请求拒绝覆盖。旧草稿不再通过前端写入。重开检查草稿比正式内容更新且内容不同才提示。恢复进入编辑器后走统一持久化，成功之前保留草稿；丢弃由用户明确触发。恢复草稿不得包含凭据，也不能在记录彻底删除后存留。

## 接口分组与错误

| 业务接口 | 关键输入/结果 |
|---|---|
| 条目创建/读取/保存 | 稳定 ID、类型、元数据、版本/编辑序号；返回正式保存结果 |
| 列表/搜索 | 关键词、固定日期区间、类型、标签模式、有无图片、分页游标；返回命中片段与范围 |
| 历史列出/预览/标重要/恢复 | recordId、revisionId；列表使用 createdAt/id 游标；恢复额外核验 expectedContentVersion、sessionId、requestId，返回新版本与新编辑会话 |
| 草稿检查/预览/丢弃 | 条目及草稿身份；丢弃不能误删后来产生的新草稿 |
| 图片导入/正文关联/读取/复制 | 有界二进制图片及目标正文、条目/会话/版本身份；原子提交正文与文件关系，逐张回执 |
| 标签新增/重命名/移除 | 标签 ID、名称；返回统一标签身份或明确冲突 |
| 回收/恢复/影响预览 | 对象身份、base revision；返回实际引用影响、到期时刻 |
| 清理执行/结果查询 | 到期项目集合；返回完成、待继续及错误，不向前端开放任意路径删除 |

错误统一区分校验失败、冲突、空间不足/写入失败、资源不存在、内容损坏和取消。保留可供用户理解的信息，日志不写正文、图片字节或密钥。前端无任意 SQL、Shell、路径读取权限。

搜索以记录日期倒序、同日创建时刻倒序、稳定 ID 消除并列；日期为包含起止日的固定日历日期。不同筛选维度取交集，标签内部根据全部/任一模式处理。时间线与日历共享查询状态；日历选日替换日期范围，保留其他筛选并可清除。

标签显示名去除首尾空白，空名拒绝；归一键使用 Unicode NFC，其他大小写/全半角不自动折叠。同键新增返回已有标签，重命名撞名返回明确冲突，不自动合并记录关联。

## 附件生命周期

导入先在受管理暂存区验证大小、实际文件签名与解码，成功后生成对象与关联。数据库提交失败时暂存对象进入可回收状态；批量逐张提交，保留成功项，失败项由用户决定重试。文件系统操作与数据库提交不能伪装为单一原子事务，使用暂存及可恢复的清理状态协调。

2026-10-20 修订：同一对象可供多个正文位置及记录使用。正文保存同步当前图片关系，移除最后一处前保存必要历史；恢复统一走编辑撤销/记录历史，不设附件区和图片独立恢复。历史单图复制经过记录/版本身份校验后写入本机剪贴板，再由用户粘贴到正文。

物理对象清理在数据库中重新核验当前正文、有效历史、消息与草稿关系；清理与新增关联通过数据库工作队列协调，防止检查后又新增引用却删文件。文件删除失败保留可重试清理状态，禁止对仍被引用对象执行删除。

图片格式、像素/文件上限、缩略图实现需要完成 macOS/Windows 解码验证后写入支持矩阵；未验证前不承诺 HEIC、动画或自动转换，不以图片理解代替附件管理。

## 删除与来源失效

30 天以删除时刻起 30×24 小时计算，使用绝对时间比较；启动后及运行中调度到期清理，不在应用关闭时新增后台服务。

先将记录标为删除中并阻止新来源选用，协调正在使用该来源的 AI 任务退出及释放任务快照，再事务清理原文版本、检索索引、恢复草稿、来源摘录及消息/附件关联。独立稿件保留，仅保留不含原文的来源失效身份。对象文件按剩余有效引用清理。不能把删除失败标为已完成，也不能让晚到 AI 结果重新落盘已删除的源快照。

风格判断失去全部有效证据后暂停用于后续生成，提示用户重新确认；用户独立手填偏好继续保留。产品可读导出和用户已有备份不被追溯清理。

## LIB-04 实施边界（2026-10-19）

Schema 6 增加恢复来源身份（不包含原文）与恢复请求回执。恢复在单一 Immediate 事务中先核验会话、内容版本及待处理草稿，保留恢复前完整快照，再创建恢复结果快照、更新当前正文/标题/日期/标签/检索并轮换会话；同一请求先重放回执，不能因轮换后的旧会话而误拒绝。原引用不改指向，恢复来源身份不强制永久保留无引用原版本。

前端查看历史前追平自动保存，打开期间保持原编辑器只读；保存失败仍留在原内容。预览保留富文本结构。恢复结果不确定时保留请求身份，后续暂忙不解除保护；重试同一请求或明确重新读取已保存内容并成功建立新会话后才能继续编辑。旧版缺少完整元数据的历史只提供正文预览，不用当前字段拼造旧快照。

启动后及运行中每小时清理创建满 90×24 小时的普通历史，打开历史列表时也执行；同一事务重新检查当前指针、重要标记、revision_pins、record_relations 和恢复草稿基版。到期版本关联的保存/恢复回执与历史附件关联随版本删除；不删除物理图片（LIB-05/07 负责有效关联及对象生命周期）。清理失败回滚，历史面板重试时显示错误；后台仅记录无正文的失败提示。

待处理恢复草稿保留到用户选择，不按普通历史期限丢弃。迁移前数据库备份独立于历史版本，本次不删除；保留期限尚未确认。外部导出和完整备份也不能通过普通历史清理追溯清除。验证证据与限制见 [LIB-04 验证记录](../development/LIB04_VERIFICATION.md)。

## LIB-07 实施约束（2026-10-21）

schema 10 为来源关系保留不含原文的失效 ID。移入回收站核验内容版本和关联影响摘要，清理编辑会话和旧请求回执；恢复/提前删除绑定具体删除时刻，拒绝恢复再删除后的旧操作。清理事务显式清除搜索文本、恢复草稿、历史与消息及附件关联；独立稿件保留，来源不可用于新的生成。应用启动、每小时及回收站刷新执行到期清理，图片清理失败保留 pending_delete 并显示重试状态。

用户确认提前彻底删除须二次确认。移入结果不确定时保持编辑只读，核对状态后才恢复编辑或清空旧编辑。迁移快照与用户备份不删除。尚无 AI 任务、主题或风格证据执行实体，后续模块接入仍须验证取消/晚到与证据失效，不能将本轮视为这些能力已完成。

## LIB-08 实施补充（2026-10-21）

schema 11/12 增加服务配置、任务、固定版本选材、连接测试结果与删除封锁。配置不含 API Key；密钥通过系统凭据服务保存。任务使用唯一请求身份，每条对话只允许一个运行任务；显式选择目标与文字来源后生成，容量不足在写入用户消息和发请求前拒绝。

来源固定版本由当前工作内容生成，包含当次标题、日期、标签与文字。对话历史只提取文字；本地图片及附件身份不进入模型请求。完成消息按顺序追加；生成结果保存为任务预览，明确采用后才创建或更新普通日记。服务响应必须满足对应协议正常完成条件；截断、拒绝、工具请求与错误不能作为完整稿件保存。

删除入口先事务写入来源封锁，取消涉及该来源的任务并清除任务选材副本，等待运行适配器退出后再移入回收站。新任务及完成提交均检查封锁和来源状态；取消超时不报告删除成功。独立稿件保留，来源关联标记失效。主题与风格证据执行实体仍待后续模块接入，不能由本轮推断已经实现。

保存失败将本次已生成结果暂留内存，显式重试只再次保存；取消/来源删除会清理该结果，退出应用会失去尚未保存的内存结果。界面显示保存失败，不自动重发收费调用。重启将运行任务标记为中断，不续发模型请求。

协议范围、真实服务和平台验证边界见 [LIB-08 验证记录](../development/LIB08_VERIFICATION.md)。

## LIB-08 聊天与日记分离（2026-10-22）

schema 13 将既有 draft 无损转为普通 text 日记，增加会话服务、默认配置、任务预览、采用凭据及已采用消息范围；schema 14 持久保存会话上下文。日记列表、日历、搜索与回收查询限定日记领域，聊天使用独立查询及回收入口。

首发事务保存聊天、消息与任务；预览生成不创建日记。采用事务校验任务、来源和目标版本，创建普通日记或补充/重整目标，保留图片与修改前历史；幂等凭据不因目标清理而失效。撤销仅在目标仍是本次采用版本时恢复修改前内容及消息范围，避免覆盖后续编辑。设置默认值只影响新聊天；已有聊天保留自己的服务。

界面使用官方 shadcn AI Elements，并保留未发送输入、未采用编辑与配置的退出保护。当前行为和验证以 [重新设计](../development/LIB08_EXPERIENCE_REVISION.md)及[验证记录](../development/LIB08_VERIFICATION.md)为准。

## 本机 CLI 配置快照（2026-10-22）

schema 15 在会话/任务中保存有效 CLI 配置 JSON（仅本应用的配置字段，不含 CLI 全量配置或凭据）。新聊天首次任务解析跟随模型及推理偏好，后续使用会话快照；任务幂等读取原有效配置。旧 Profile 缺少新字段时保持固定模型语义。CLI 目录与生成分别核验，目录保留显示名与推理能力并逐页读取，跟随值不使用目录推荐默认项替代。测试取消绑定独立请求身份，与普通生成任务分开，避免跨测试取消。具体行为见 [CLI 规格](../development/LIB08_LOCAL_CLI_DESIGN.md)。
