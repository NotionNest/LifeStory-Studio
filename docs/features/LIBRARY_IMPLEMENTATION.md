# LIB-01：资料库详细实施设计

日期：2026-10-15。状态：LIB-01 契约与图片能力验证已完成；LIB-02 文字记录已实现，验证见交付记录。产品依据：[已确认评审稿](LIBRARY_REVIEW.md)。本文件为实施契约，不新增产品范围；实际 API 语法及依赖接入在编码时按项目规则检索当前文档。

## 数据职责

| 数据 | 身份与写入规则 |
|---|---|
| 资料条目 | 稳定 ID、类型（文字/对话/整理稿）、可选标题、记录日期、创建时区、绝对创建/修改时刻、当前版本及回收站状态 |
| 内容版本 | 不可变 ID、条目 ID、结构化编辑文档、检索文本、创建时刻、重要标记；正文节点具有稳定段落身份 |
| 对话消息 | 会话 ID、顺序、角色、消息内容与附件关联；原始用户消息与模型回应明确区分，追加幂等 |
| 来源关系 | 稳定来源版本及片段；正文中的图片引用使用附件 ID，不保存任意本地路径 |
| 恢复草稿 | 条目 ID、base revision、编辑序号、内容及更新时间；与不可变正式版本分离，不参与日常检索 |
| 图片对象与关联 | 对象摘要、受管理相对路径、类型与尺寸；记录版本/消息的关联独立于物理文件，回收站期限属于关联 |
| 标签 | 稳定标签 ID、显示名及归一键；条目多对多关联，移除标签不删除条目 |
| 清理状态 | 删除时刻、到期时刻与待清理对象；物理文件删除可在事务提交后继续执行，不把失败误报为已彻底清理 |

迁移在既有数据库工作线程中执行，保留事务回滚及更高 schema 拒绝写入。结构化文档是编辑来源，检索文本由同一保存操作生成；不使用搜索索引反向恢复正文。

## 保存与恢复契约

保存输入包含条目 ID、base revision、幂等请求 ID、客户端编辑序号、元数据和结构化内容。数据库事务校验当前版本与附件关联，写入新版本并更新当前指针、索引与必要关系，返回实际版本和编辑序号。

界面只将已成功保存的对应编辑序号标为已保存。保存期间有新输入时仍保留待保存状态；单条记录串行提交，不能让旧回执覆盖新编辑。版本不匹配返回冲突与当前版本身份，不自动重写或合并正文。

初始执行参数：停止输入 1 秒提交自动保存；持续输入期间最长 5 秒提交一次；手动保存立即触发。中文输入法组合期间不序列化半成品，结束组合后继续调度。这些参数属于实现起点，按实际输入体验验证，不构成每个按键写入版本的要求。

正式保存创建不可变版本，不就地合并版本；不变内容不创建重复内容版本。历史列表按编辑时段分组展示，底层版本保持可引用。普通历史从版本创建时刻起保留 90×24 小时；清理时重新检查当前指针、重要标记与引用保护。

恢复草稿按编辑序号保存到应用管理的本地恢复存储，原子替换且保留 base revision；写入失败必须可见，不承诺此时有异常退出恢复保护。重开检查草稿比正式内容更新且内容不同才提示。恢复进入编辑器后新建正式版本，成功之前保留草稿；丢弃由用户明确触发。恢复草稿不得包含凭据，也不能在记录彻底删除后存留。

## 接口分组与错误

| 业务接口 | 关键输入/结果 |
|---|---|
| 条目创建/读取/保存 | 稳定 ID、类型、元数据、版本/编辑序号；返回正式保存结果 |
| 列表/搜索 | 关键词、固定日期区间、类型、标签模式、有无图片、分页游标；返回命中片段与范围 |
| 历史列出/标重要/恢复 | 条目、目标版本、base revision；恢复返回新版本 |
| 草稿检查/预览/丢弃 | 条目及草稿身份；丢弃不能误删后来产生的新草稿 |
| 图片导入/关联/移除/恢复 | 授权文件输入或粘贴字节、目标条目及 base revision；逐张结果与关联身份 |
| 标签新增/重命名/移除 | 标签 ID、名称；返回统一标签身份或明确冲突 |
| 回收/恢复/影响预览 | 对象身份、base revision；返回实际引用影响、到期时刻 |
| 清理执行/结果查询 | 到期项目集合；返回完成、待继续及错误，不向前端开放任意路径删除 |

错误统一区分校验失败、冲突、空间不足/写入失败、资源不存在、内容损坏和取消。保留可供用户理解的信息，日志不写正文、图片字节或密钥。前端无任意 SQL、Shell、路径读取权限。

搜索以记录日期倒序、同日创建时刻倒序、稳定 ID 消除并列；日期为包含起止日的固定日历日期。不同筛选维度取交集，标签内部根据全部/任一模式处理。时间线与日历共享查询状态；日历选日替换日期范围，保留其他筛选并可清除。

标签显示名去除首尾空白，空名拒绝；归一键使用 Unicode NFC，其他大小写/全半角不自动折叠。同键新增返回已有标签，重命名撞名返回明确冲突，不自动合并记录关联。

## 附件生命周期

导入先在受管理暂存区验证大小、实际文件签名与解码，成功后生成对象与关联。数据库提交失败时暂存对象进入可回收状态；批量逐张提交，保留成功项，失败项由用户决定重试。文件系统操作与数据库提交不能伪装为单一原子事务，使用暂存及可恢复的清理状态协调。

同一受管理对象可被多个关联使用。移除当前附件关联会创建新正文版本，移除其中相关呈现并将关联移入回收站；旧版本关联保持有效。恢复默认回到附件区，不自动覆盖当前正文位置；需要原布局时预览并恢复历史版本。

物理对象清理在数据库中重新核验有效版本、消息关联与回收期限；清理与新增关联通过数据库工作队列协调，防止检查后又新增引用却删文件。文件删除失败保留可重试清理状态，禁止对仍被引用对象执行删除。

图片格式、像素/文件上限、缩略图实现需要完成 macOS/Windows 解码验证后写入支持矩阵；未验证前不承诺 HEIC、动画或自动转换，不以图片理解代替附件管理。

## 删除与来源失效

30 天以删除时刻起 30×24 小时计算，使用绝对时间比较；启动后及运行中调度到期清理，不在应用关闭时新增后台服务。

先将记录标为删除中并阻止新来源选用，协调正在使用该来源的 AI 任务退出及释放任务快照，再事务清理原文版本、检索索引、恢复草稿、来源摘录及消息/附件关联。独立稿件保留，仅保留不含原文的来源失效身份。对象文件按剩余有效引用清理。不能把删除失败标为已完成，也不能让晚到 AI 结果重新落盘已删除的源快照。

风格判断失去全部有效证据后暂停用于后续生成，提示用户重新确认；用户独立手填偏好继续保留。产品可读导出和用户已有备份不被追溯清理。
