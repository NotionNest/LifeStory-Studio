# 数据、IPC 与 AI 任务契约提案

编写日期：2026-10-14。确认日期：2026-10-15。状态：关联 DEC-12—14 已由用户确认，对应 REQ-01—15；实现与验证尚未开始。

## 1. 本地资料组织

通过平台应用数据目录 API 定位资料根目录，不硬编码用户路径。建议组织：数据库、不可变图片对象、缩略图缓存、任务临时目录及不含原文/密钥的诊断日志。资料目录不要默认位于系统云盘目录。

数据库保存元数据和内容版本，图片复制进入受管理目录并校验文件类型、大小与解码结果；记录保存 attachment ID，不依赖原始外部路径。缓存可重建，不纳入资料完整性的唯一依据。

## 2. 核心实体

| 实体 | 内容 | 关系与规则 |
|---|---|---|
| Record / RecordRevision | 日期、时区、标题、编辑 JSON、可检索文本、版本 | 已提交版本不可变；编辑创建新版本，不覆盖旧引用 |
| Conversation / Message | 文字对话及发送顺序 | 日记整理稿关联实际消息集合；续聊仍受本次资料范围约束 |
| Attachment / AttachmentLink | 图片 ID、摘要、大小、类型、相对路径 | 关联记录/消息；备份保存对象，不自动发送给 AI |
| SourceRef | 记录版本、段落 ID、原文片段与摘要 | 主题、回顾、审查、风格证据共同引用；生成引用由应用校验 |
| Topic / TopicSource | 主题方向与所选来源 | 同一记录可以参与多个主题 |
| VlogProject / ArtifactRevision | 项目、故事结构、旁白与修改版本 | 引用来源独立于输出文本；修改项目不修改日记 |
| Shot | 顺序、画面、旁白/声音、预计时长、用户说明的拍摄状态 | 不管理视频文件；“已拍摄”来自用户操作，不由模型断言 |
| Review / Exercise | 审查意见、问题、练习与反馈 | 关联原文版本，不能仅存悬空字符偏移 |
| StyleClaim / StyleEvidence | 偏好、证据与确认状态 | 仅用户确认的偏好进入后续任务 |
| LifeReview | 周/月/年度及自选资料、回顾稿 | 显示周期、时区、实际范围；保留来源 |
| AiTask / TaskSource | 入口、模型、状态、选定版本、提示模板版本、结果 | 每次任务输入可解释；默认不记录密钥和推理全文 |
| ProviderProfile | 协议、端点、模型和能力 | 仅存凭据引用；秘密位于本机私有凭据文件 |

段落 ID 与版本共同定义证据。编辑后旧证据仍定位旧版本；无法核对的引用标为无效，不伪造高亮。采用稿件使用 base revision 检测编辑冲突，不让晚到的 AI 结果覆盖新修改。

## 3. 保存、搜索、删除与迁移

保存用事务提交版本、附件关系与索引，返回保存版本号；前端只有收到成功回执才显示已保存。数据库工作放专用线程/队列，不阻塞 UI，也不持有数据库锁等待模型网络响应。

中文关键词按字面子串语义设计。建议三字符及以上使用 FTS5 trigram 筛选并核对原文，短词及带查询语法字符的词用参数化字面匹配；这是明确的查询规则，不是索引故障后的兜底。索引不可用应报告错误。FTS5 trigram 的 MATCH 无法命中少于三个 Unicode 字符的查询，必须覆盖“工作”等短词测试。[SQLite 官方 FTS5](https://sqlite.org/fts5.html#the_trigram_tokenizer)

删除前显示被引用项目、回顾与风格证据的影响；删除操作须同时定义版本、索引、消息快照和附件处理。删除后不可继续把原文作为有效证据。既有用户导出的备份无法由应用追溯清除，需在删除界面说明。

迁移有编号和事务，执行前建立可恢复快照。遇到更高版本 schema 则拒绝写入并提示兼容性；不自动修改旧文件。应用级资料加密及加密备份尚未决定，不能宣称当前方案已加密日记。

## 4. 导出与完整恢复

可读导出建议：日记/回顾/旁白使用 Markdown；分镜和拍摄清单使用 Markdown 表格与 CSV，正确处理换行、编码、引号，并对电子表格公式注入提供安全处理。可读导出不等于完整恢复格式。

完整备份建议使用带格式版本的归档：manifest、SQLite 一致性快照、所引用图片对象与校验摘要，不包含 API Key。备份期间通过应用写入协调锁固定资料状态，使用数据库 backup API，暂缓删除被快照引用的附件；未完成的归档不替换已完成文件。[SQLite Online Backup](https://sqlite.org/backup.html)

恢复先在暂存位置检查格式版本、路径安全、摘要、数据库完整性和引用关系，再关闭资料写入，切换完整资料目录。恢复失败保留原资料；新设备恢复后重新配置密钥。备份位置、保留策略、密码保护待确认。

## 5. 前后端命令边界

以下是业务契约名称，实施阶段再生成并验证具体 Rust/TypeScript 类型。

| 命令组 | 输入与输出规则 |
|---|---|
| record.save / list / search | ID、base revision、编辑内容与筛选条件；返回版本或分页结果 |
| conversation.append | 会话 ID、消息内容与幂等请求 ID；返回保存消息 |
| attachment.import / image / copy | 授权图片字节及目标正文；原子提交图片与正文；按记录/历史身份读取和复制，不接收任意路径 |
| topic.save / project.save | 来源版本 ID、稿件与 base revision；校验引用和冲突 |
| style.confirm / reject | claim ID 与用户决定；不允许模型直接确认 |
| review.create | 周期、时区与用户选定来源；返回任务 ID |
| ai.start / cancel / inspect | 任务类型、选定来源与 provider ID；模型 URL 不从单次生成请求随意覆盖 |
| export.start / backup / restore | 用户选定目的地与导出范围；返回任务状态和实际结果 |
| provider.configure / test | 配置端点和密钥写入操作；检测仅发合成文本，不用日记 |

前端不接收执行任意 SQL、Shell 或读取密钥的通用命令。Tauri 命令权限显式配置；Channels 仅传当前任务必要内容，携带任务 ID 与递增序号，不广播日记正文。

## 6. AI 任务生命周期

`准备 → 运行 → 校验 → 草稿已保存`；任一阶段可进入 `取消` 或 `失败`。草稿被采用另建稿件版本，不改写任务状态假装重新生成。

1. 用户看到资料范围与接入入口，确认后固定版本快照；风格偏好也列入使用范围。
2. 超出上下文容量时明确预算及来源，不静默丢弃资料；可设计用户可见的分批分析，所有批次只使用选定资料。
3. 运行中可取消，不自动换模型、换入口或重复请求。已有流式片段可保留为未完成内容，但不能标成完整稿件。
4. 输出做 schema、长度、来源 ID 和原文引用检查；结构不合格标明失败或待修订，不自动发起收费修复请求。
5. 取消后晚到结果不得进入正式稿件。进程异常或应用重开后，未完成任务标为中断，用户决定是否重新运行。

能力矩阵决定入口能执行哪些任务：文字对话、流式、取消、结构化结果等分别验证。提供方宣称“兼容”不等于全部能力相同；不能只填 Base URL 就保证任意模型可用。


2026-10-29 API 配置只读元数据补充（REQ-11/12/13 / TASK-10）：hasKey 表示本机凭据实际可读，keyScope 是由 Rust ConnectionTarget 统一定义的绑定目标快照；前端只按返回字段和值比较编辑草稿，原生凭据复用也用同一目标定义比较。二者均忽略客户端传入值，读取/保存配置响应时由后端重建；不向前端返回密钥或长度，不改变备份排除凭据与目的地变化须重填的规则。
