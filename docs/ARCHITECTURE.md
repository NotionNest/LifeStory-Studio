# 架构与技术边界

本页是当前架构入口；实现与验收状态见 [项目跟进](STATUS.md)，产品范围与已确认决策见 [产品文档](PRODUCT.md)。未实现的产品模块不因架构设计而视为完成。

## 技术组合与平台

用户已确认独立 Tauri 桌面应用，同时面向 macOS 和 Windows。前端使用 React、TypeScript、Vite、Tailwind CSS、shadcn/ui 与 Tiptap；页面导航采用 React Router Data Mode 和 Hash 路由。Rust 侧管理 SQLite/rusqlite、文件、有限 IPC 和 AI 适配，HTTP 模型服务使用 reqwest，本机 Codex 使用 App Server stdio 协议。npm 与 Cargo 锁文件固定依赖版本；具体版本以项目锁文件为准。

采用 SQLite 是为了事务、版本及多对多引用；数据库访问集中在 Rust 侧，由专用线程协调。Tiptap 保存结构化编辑器文档，并维护可检索文本；原文定位和版本一致性仍由应用保障。前端使用 Vite 输出桌面静态资源，不引入服务端渲染；Tailwind 管理布局及语义主题，shadcn 源码组件按需加入。以上是已确认的技术方向，不意味着完整备份恢复、全部模型协议或未来功能已经实现。

最低系统版本、CPU 架构和发行方式仍待决定；已有 Windows 主链路确认不等于全部兼容组合与发行验收通过。依赖的 WebView 兼容范围需结合目标系统实际验证，不能只凭编译成功承诺支持。

## 应用分层

- **前端**：`src/app` 负责入口和依赖装配；路由管理页面身份，窗口级会话保留聊天、配置草稿及离开保护；日记、聊天与设置按业务组织。当前归属见 [应用结构](architecture/APP_STRUCTURE.md)，导航及会话规则见 [页面架构](architecture/FRONTEND_NAVIGATION.md)。
- **桌面边界**：前端通过 `services/` 调用有限 Tauri 命令和具名事件；Rust 在边界校验请求，负责业务协调及本机能力。权限不得仅依赖前端限制。
- **本地数据**：SQLite 管理记录、版本、引用和任务等数据；原图及引用受保护。保存与恢复需处理事务、会话身份、幂等、迁移备份和失败回滚。完整备份恢复及引用验证仍待实施。细节见 [数据与 AI 契约](architecture/DATA_AND_AI.md) 与 [资料库实施说明](features/LIBRARY_IMPLEMENTATION.md)。
- **AI 任务**：由用户选择已配置的 API 服务或本机 Codex，限定本次任务使用的资料与目标，处理状态、取消、失败及迟到结果；失败不自动切换服务。模型兼容和权限隔离不能因配置成功就视为已全面验证。

## 隐私与资料控制

资料本地保存，不做云同步；AI 只能使用用户明确选定的资料。外部服务收到资料后的保留政策由该服务决定。本机工具不得默认自由遍历资料库，实际隔离需按协议和平台验证。图片保存不代表默认发送给 AI。

按用户确认的 DEC-18，API Key 明文保存在应用私有配置文件，不加入应用备份或导出；前端不读回已保存密钥，旧钥匙串凭据不自动迁移。资料加密及备份保护仍待决定。详细约束见 [产品决策](PRODUCT.md#产品决策与待确认事项)和 [数据与 AI 契约](architecture/DATA_AND_AI.md)。

## 后续能力

写作与风格、主题与 Vlog、生活回顾及完整备份恢复继续沿既定顺序细化；当前架构为这些能力预留需求和边界，不宣称已有实现。验证证据、平台限制及下一步以 [STATUS](STATUS.md) 为准。

前端使用 Vitest 验证关键交互，Rust 使用单元及真实存储/协议集成验证复杂规则；桌面端到端方案曾考虑 WebdriverIO Tauri service 和仅测试构建启用的 embedded provider，这不代表该链路已经建立或通过。具体执行范围以 [测试策略](process/TESTING_POLICY.md) 为准，签名安装、升级和系统原生能力仍需目标平台验证。
