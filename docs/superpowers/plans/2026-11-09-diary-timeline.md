# 记录首页时间线实施方案

**目标：** 将 REQ-02 的记录列表改为用户认可的时间线，同时保留已有浏览和数据保护行为。

**方案：** 沿用日记首页、筛选、分页和日历会话；列表按记录日期分组，显示标题、摘要、标签和正文图片缩略图。月份导航依据完整筛选结果，而不是仅依据已加载页；选择月份定位对应记录。图片沿用本地受权限保护的预览接口，按需加载。所有日期与图片信息来自真实记录，不使用示例数据。

**技术：** React、TypeScript、Tauri、Rust、SQLite 和现有语义主题。

## 行为与验收

- 时间线按记录日期降序，日期相同保持创建时间及稳定 ID 的原排序；同日多篇各自展示。日期以记录日期为准，创建时间单独标明，不把两者混同。
- 年份和月份导航覆盖当前筛选下全部记录，点击可到达目标月份，即使目标不在已加载页；切换筛选后不得保留过期导航或过期请求结果。
- 图片按正文顺序展示，使用真实本地缩略图；图片加载失败可恢复，不阻止打开记录。无图片、无标题、长文本及无结果均可用。
- 月份跳转须支持目标位置前后连续分页，不能为定位旧月份顺序读取全部历史；恢复时保留目标锚点。月份索引和定位使用同一筛选与排序，数据变化时重新定位而非静默跳错。
- 图片从当前正文节点提取，并核对当前有效的记录图片关系；固定缩略图空间，按需加载、限制并发并释放对象 URL。重试操作独立于打开记录的按钮。
- 明确区分记录日期与创建时间；年份切换和滚动时当前月份状态一致，筛选变化或记录变化时更新索引。
- 保留列表/日历、日期与标签筛选、新建、分页、错误重试及打开记录后返回的视图、滚动与焦点。深浅主题、窄窗口、键盘操作可用。
- 不新增示例图里的收藏、自动标签、账户或其他未实现功能；桌面实机视觉由用户验收。

## 任务

1. **数据契约**：修改 `src-tauri/src/library_query.rs` 和 `src/services/search.ts`，以有界方式提供筛选后的月份索引、创建时间及正文图片标识；在 `src-tauri/tests/library_query.rs` 验证筛选、分页和图片顺序。
2. **浏览状态**：修改 `src/features/library/useLibraryQuery.ts`，支持按月份定位及异步请求顺序保护，保留返回现场；在 `LibraryBrowser.test.tsx` 覆盖跨页月份定位和旧请求。
3. **时间线视图**：修改 `LibraryBrowser.tsx` 和 `browser.css`，复用本地图片预览，按概念图实现日期轴、摘要、标签、缩略图与月份导航；保留日历和已有入口，处理长文、空态、错误与键盘焦点。
4. **验证与文档**：运行受影响的前端交互测试、Rust 查询集成测试、项目检查和构建；用合成数据检查实际界面。更新 `docs/features/DIARY.md`、`docs/VERIFICATION.md` 与 `docs/STATUS.md`，如实区分自动检查、桌面实测和用户验收。
