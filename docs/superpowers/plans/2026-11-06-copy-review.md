# REQ-04 文案审查实施计划

> 执行前遵循项目测试边界和已确认需求；本计划是工程方案，实施和用户实机验收尚未完成。

**目标：** 对已有日记整篇正文进行低干预基础校对，逐条展示并由用户决定处理，结果仅在当前会话中存在。

**架构：** 日记编辑器生成包含段落身份的内存快照；原生层以单独的临时任务复用既有服务配置、凭据、模型解析及提供商调用，不使用会落盘的聊天任务。模型返回结构化建议，应用校验来源和位置，通过编辑器事务呈现标记并安全采用。

**技术：** 既有 React、Tiptap 3/ProseMirror、Tauri、Rust、现有 Codex/API 适配器；不预设新增依赖或数据库迁移。

## 已确认边界

以 [需求规格](../../features/COPY_REVIEW.md)为准：整篇正文、不审查选中片段；主动开始、可选模型、逐条处理；不保存审查结果；切换记录、删除、重新打开、退出时丢弃并取消。标题和图片不发送；不访问其他日记。用户未确认扩展范围或自动重试。

## 现状与关键设计

- `RecordEditor.tsx` 拥有 Tiptap 实例和 `useRecordPersistence`，`DiaryEditorPage.tsx` 提供页面操作，`DiarySessionProvider` 的编辑会话可能跨页面存活，不能单靠组件卸载判断切换。需要在会话切换、删除、重新进入、退出等实际生命周期显式失效，关闭校对界面本身是否丢弃不扩展用户决定。
- `ai.rs` 的 `ai_prepare`、`ai_partial`、`ai_finish` 会保存请求、来源、部分结果和输出，不能直接用于不保存的校对。复用 `ai_providers::generate_with_summary`、已有服务配置/密钥读取、Codex 模型与强度校验和取消机制；校对任务不写 `ai_tasks`、来源、聊天消息或日志。服务端处理与保留由选择的服务决定。
- 发起前在编辑器取当前正文内存快照，不依赖滞后的数据库保存版本；每个可审查文本块分配本次快照内的稳定编号和完整文字。快照映射精确记录 ProseMirror 位置、块边界和格式；图片、标题及其他记录不进入发送文本。使用明确编码契约：模型引用块 ID、精确原文及必要上下文，不信任模型计算 UTF-16 偏移。重复片段无法唯一映射时仅显示建议，不提供定位或替换，不能靠猜测匹配。
- 单次请求包含完整正文和校对提示，检查已有 `context_chars` 与输出约束；超限、输出截断、结构错误或校验不完整应明确失败，不能显示为全部检查成功。不得自动分批、缩减内容、切换服务或重试；模型输出是非可信数据，限制大小、类别与字段，引用必须属于快照，不执行内容中指令。
- 输出协议使用版本化 JSON：例如 `{"version":1,"suggestions":[{"id":"1","category":"consistency","references":[{"blockId":"b1","quote":"小李"},{"blockId":"b3","quote":"小黎"}],"reason":"称谓可能不一致，请核对","replacement":null}]}`。类别对应已确认范围；一条可引用多处，用于跨段一致性检查，每处独立核对并标记；任一引用失效时整条标记过期，不提供自动替换。多引用和跨块建议只提示，单一且安全定位的文字才可提供替换。提示也必须有至少一个合法引用，避免悬空意见。
- 只接受提供商报告正常完成且完整解析的顶层对象、已知版本及字段类型；空 `suggestions` 表示未发现建议。JSON 截断、未知版本、缺字段、重复建议 ID、无效类别、缺失或不属于快照的引用、长度/数量越界，整次标记失败，不过滤后冒充完整结果。合法引用在块中出现多次属于定位不唯一，保留建议但禁止自动定位和替换。正常完成只能表示请求与格式完整，不能证明模型发现所有问题。
- 编辑器采用 ProseMirror decorations，而非写入文档的 mark；映射事务中的位移并在点击、采用前核验原文、结构与当前版本。只允许可以证明安全的单段纯文本替换；跨段、跨图片或格式边界的建议可以提示，但未能确保完整保留格式和结构时不可自动替换。单次替换为独立可撤销事务，触发现有自动保存；其他建议与重叠位置在每次编辑或采用后重新校验。
- 生命周期用请求 ID、会话代次和取消令牌共同约束；启动前注册可取消请求并绑定记录及代次，网络发送前再次检查取消和记录有效性，已失效时不发送。删除后原生取消并拒收终态，导航和退出时拒绝迟到回包，回收进程和内存；已经发出的内容无法从远端撤回。记录进入回收站或外部变化等要依据权威状态失效，不能只依赖 React 视图。
- 现有 `ChatModelControls.tsx` 有聊天专属名称与无障碍标签，模型选择能力须迁至合理共享位置并同时更新聊天调用及其测试；不让 library 功能反向依赖 chat。原生层再次验证选中的配置、模型、强度及凭据绑定；不会回写全局默认。
