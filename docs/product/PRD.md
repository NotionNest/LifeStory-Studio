# LifeStory Studio 产品需求文档

版本：评审稿 1.0 · 2026-10-14

产品负责人：用户；整理与跟进：Codex。

状态：核心方向已明确，详细行为与质量要求为本次提案，待审阅。Tauri 已由用户指定，其他技术选型未确定。

## 1. 产品概述

LifeStory Studio 是独立的桌面创作产品，帮助用户持续记录生活、整理日记、审查文案、提升写作，并从单篇或多篇记录中提炼 Vlog 主题，完成故事结构、旁白及分镜。长期积累的原文和经过用户确认的风格档案，让创作成果更接近用户自己的表达。

产品价值链：生活记录积累 → 可理解和检索的资料 → 写作成长与故事发现 → 可执行的影像策划。

## 2. 用户与问题依据

首要用户是当前产品发起者：持续写日记，希望创作日常 Vlog，并希望改善写作。类似个人创作者是潜在用户，尚未做独立访谈或验证市场需求；定价、规模和增长指标不在本次已有证据内。

| 问题 | 用户证据 | 产品响应 |
|---|---|---|
| 记录需要整理，文案需要审查 | “整理日记，审查文案，提升写作水平” | 日记整理与可解释的写作辅导 |
| 以单篇日记直接生成视频限制自由度 | “从我的单篇或者很多篇中整理出主题” | 独立主题与多对多资料引用 |
| 希望长期了解自己的表达习惯 | 明确要求个人写作风格档案、减少 AI 腔 | 基于原文证据的风格分析与反馈 |
| Skill 形式不能承载完整产品体验 | 最新决定做成独立 Tauri 桌面软件 | 统一的记录、资料与创作工作空间 |

用户要完成的任务：随时留下真实生活；知道文字哪里可以改善以及为什么；在历史记录中找到值得讲述的故事；拿着旁白和分镜准备拍摄；长期积累属于自己的表达。

## 3. 产品原则

真实记录可追溯；原文与生成稿区分；个人表达由用户决定；主题自由组合；创作建议不伪装为事实；用户可以拒绝 AI 修改；围绕完整产品目标实施。

用户已确认：独立桌面产品、Tauri、记录与审稿/训练、单篇及跨篇 Vlog、个人风格档案。

平台范围（2026-10-14 确认）：首次正式交付同时支持 macOS 和 Windows；最低系统版本与 CPU 架构在技术方案阶段确定。

AI 接入（2026-10-14 确认）：支持用户自配模型服务与 API Key，同时支持连接用户已安装的 Codex 等 AI 工具。具体工具范围、接口与认证方式在技术研究中确定，用户主动选择接入方式，失败不自动切换。

数据边界（2026-10-14 确认）：资料本地保存，不做云同步；AI 只使用当前任务明确选定的资料。通过远程模型服务处理所选资料属于该次 AI 调用，不代表云端资料同步。本机工具权限限制需通过实现验证。

输入范围（2026-10-14 确认）：文字、对话及图片附件。视频素材管理不纳入首次交付；语音转录和图片/视频内容理解未纳入已确认范围。Vlog 策划、旁白与分镜仍属于核心需求。

回顾与输出（2026-10-14 确认）：加入周/月/年度生活回顾，支持导出旁白、分镜和拍摄清单，不直接连接剪辑软件。

本次提出待审阅：版本管理、来源定位、导入导出、数据删除行为、AI 任务状态与隐私控制等详细质量要求。这些不应被误记为此前已确认。

## 4. 核心用户流程

### 记录与写作

2026-10-15 记录单位确认：同一天允许多条独立记录，再按需选择来源整理成日记；原始记录保留，整理稿独立保存。详细行为持续整理于 [资料库与日常记录规格](../features/LIBRARY_AND_RECORDING.md)。

创建记录 → 自由书写并保存 → 按需整理 → 对照原文查看建议 → 选择采用或自行修改 → 按需进入写作训练。

记录入口（2026-10-15 确认）：支持直接书写或开始对话，已有文字也可发起关联对话；原文、对话与整理稿分别保留。

对话回应（2026-10-15 确认）：默认轻回应、少量追问，需要补充时一次问一个问题；不主动审稿，用户主动要求后再整理。

对话式记录已纳入：用户可以通过文字对话补充经历，在用户结束讲述或主动要求整理后形成草稿。支持图片附件；附件与对应记录关联并本地保存。语音输入和自动图片理解不属于当前确认范围。

删除规则（2026-10-15 确认）：普通删除进入回收站，30 天后自动彻底删除，清理前可恢复；彻底删除清除原文、历史及引用摘录，保留独立创作稿并标记来源已删除，删除前展示影响；稿件中已写入的相关内容仍保留。

重开恢复（2026-10-15 确认）：发现较新的本地恢复草稿时提示并支持预览，由用户选择恢复或丢弃，不静默覆盖正式内容；恢复以实际落盘内容为限。

历史版本（2026-10-15 确认）：自动保留历史，也可手动标记重要版本；恢复旧版创建新版本，保留恢复前内容及已有引用。普通历史保留 90 天，重要或被引用版本随记录保留，记录彻底删除时一并清理；历史合并及清理执行细则待细化。

保存方式（2026-10-15 确认）：文字记录自动保存，同时可手动立即保存；显示实际保存状态，切换记录或正常退出前处理待保存修改，失败时保留编辑内容并提醒。尝试离开时可手动重试或主动另存；只有明确放弃修改才丢弃未保存内容。

记录日期（2026-10-15 确认）：默认今天，可修改记录日期，保留实际创建时间；后续编辑不自动改变记录日期。记录日期保持固定，系统时区变化不移动旧记录；新建按当前系统时区确定今天并保存当时时区，创建/修改时间保存为绝对时间，可按当前时区显示。

内容呈现（2026-10-15 确认）：原文为主，通过关联区打开对话及独立整理稿，按需并排对照；跨篇整理稿可以回到各条来源。

附件清理（2026-10-15 确认）：附件区移除时展示并移除当前相关呈现，附件关联进入回收站保留 30 天；历史或其他记录仍引用的图片文件继续保留，无有效关联且所有保留期结束后才清理文件。

图片导入（2026-10-15 确认）：文件选择、拖入、剪贴板粘贴均支持，可一次添加多张；导入成功后复制到应用管理的本地目录，不依赖外部原文件。

图片呈现（2026-10-15 确认）：支持文字引用图片附件并在鼠标移入时预览，同时支持正文插图与统一附件区，关联同一受管理附件。删除正文插图或图片引用只移除该处呈现，附件区单独管理；从附件区移除前展示引用影响并确认。

搜索与筛选（2026-10-15 确认）：搜索当前标题、正文及对话消息，支持记录日期、类型、标签、有无图片组合筛选；多标签可选全部或任一满足。默认排除旧版本、回收站、图片内文字与独立 Vlog 项目。

标题与标签（2026-10-15 确认）：均可选；无标题时列表以正文首段或首条用户消息摘要展示，摘要不写入正式标题，标签手动管理，不默认由 AI 分类。

资料库浏览方式（2026-10-15 确认）：默认时间线，标签与搜索辅助；可切换日历视图，选择日期查看当天全部记录。

### 主题与 Vlog

选择单篇、多篇或指定范围的记录 → 提炼主题候选及依据 → 用户选择或自建主题 → 调整引用内容 → 建立 Vlog 项目 → 故事结构 → 旁白 → 分镜与拍摄准备 → 修改、保存、导出。

一个主题可产生多个项目；一篇记录可被多个主题或项目引用。引用源更改后，已有项目内容保留，用户能看懂引用版本及变化。

### 风格积累

选择用户原文 → 分析表达习惯并展示原文依据 → 用户确认、纠正或拒绝 → 更新风格档案 → 后续整理和旁白按已确认偏好生成 → 用户反馈修正。

## 5. 功能需求与验收条件

下表是目标产品需求，不是已实现清单。所有需求均等待后续规格化及开发验证。

| ID | 能力与用户故事 | 验收条件 |
|---|---|---|
| REQ-01 | 我能创建、编辑和保存生活记录，长期保留原文 | 保存后关闭重开内容一致；编辑有保存状态；保存失败明确提示且当前编辑内容不被清空 |
| REQ-02 | 我能浏览和检索积累的记录 | 可按日期与关键词找到记录；结果能进入原文；空记录库与无结果有明确状态；查询范围对用户可见 |
| REQ-03 | 我能把零散记录整理成日记，并掌握修改 | 原文与整理稿可分别查看；生成不覆盖原文；可以修改、拒绝或采用稿件；缺少事实时询问或明确标记 |
| REQ-04 | 我能审查文案并知道修改理由 | 指出具体原文片段、问题、理由及建议；区分结构与表达问题；不会未经操作替换全文 |
| REQ-05 | 我能通过练习提升写作 | 从实际问题提出练习；保留我的练习与反馈；能回看原有问题；不得仅以自动重写冒充训练 |
| REQ-06 | 我能从单篇或多篇日记发掘主题 | 能自由选取及移除来源；主题候选展示对应原文依据；可手动建主题；资料不足不虚构故事 |
| REQ-07 | 我能将主题组织为独立 Vlog 项目 | 项目保存主题、引用、故事结构及稿件；多篇引用与多项目复用成立；编辑一个项目不更改其他项目及原文 |
| REQ-08 | 我能写出和调整适合自己的视频旁白 | 可设创作方向与目标时长；旁白可编辑、保存版本；时长仅作为估计展示；用户事实与创作提议可区分 |
| REQ-09 | 我能用分镜准备拍摄与剪辑 | 分镜包含顺序、画面、旁白/声音、预计时长与拍摄状态；已有素材必须有用户提供的依据；未证实镜头标为待确认或建议补拍 |
| REQ-10 | 我能管理个人表达风格 | 分析基于用户原文，展示可定位的证据；用户可确认、纠正、移除判断；未确认判断不当作长期偏好；修改稿不冒充用户原始风格样本 |
| REQ-11 | 我能了解 AI 正在处理什么并控制过程 | 显示选定资料范围及任务状态；可取消；失败说明原因，保留既有内容；重试由用户操作，不自动切换未授权服务或方案 |
| REQ-12 | 我能携带、保护和恢复自己的创作资料 | 支持导出原文和创作成果；导出失败有提示；可验证恢复后引用关系成立；格式、备份方式与存储实现下一阶段确定 |
| REQ-13 | 我能用文字对话记录经历并整理成日记 | 对话可保存与重开；用户明确要求后生成独立草稿；原对话保留，不虚构缺失事实 |
| REQ-14 | 我能给记录添加图片附件 | 图片本地保存并关联记录；重开后可查看；添加/移除失败有明确反馈；导出和恢复保留附件关系；图片不默认发送给 AI |
| REQ-15 | 我能从选定记录回顾一周、一月或一年 | 可选择周期、时区与资料范围；回顾结果有原文来源并独立保存；资料不足不推断未记录的经历；可编辑和导出 |

REQ-12 的策划输出必须包含旁白、分镜和拍摄清单；具体可读格式建议为 Markdown 与 CSV，完整恢复格式见架构提案。导出不要求连接剪辑软件。

REQ-01/02/06/07/10 直接支撑长期积累与创作自由度；REQ-03/04/05/08/09 支撑创作质量；REQ-11/12 是本次提出的完整产品质量要求。其具体发布范围需用户审阅决定。

## 6. 业务与资料规则

- 原始记录、整理稿、主题、项目及风格档案有稳定身份和来源关系。
- 修改用户原文与采用 AI 整理稿是不同操作，须保留足够版本信息以解释引用。
- 删除被引用的记录时展示影响，由用户决定；不能静默破坏项目或保留用户以为已删除的隐私内容。删除及历史清理细则待规格确认。
- AI 仅使用当前任务允许的资料范围；新会话不能假设存在历史资料。
- 主题依据和风格证据可回到对应原文；原文删除后相关证据不再标为可用。
- 风格档案是可调整偏好，不是对用户固定人格或心理状况的诊断。
- 日期归档应明确用户时区；创作的主题组织不受日期顺序限制。

## 7. 质量、隐私与桌面体验要求（提案）

| 方面 | 要求 | 验证方式 |
|---|---|---|
| 数据可靠性 | 保存失败、异常关闭、升级不造成静默丢失或引用损坏 | 保存/重开、异常中断、升级与恢复场景 |
| 隐私 | 用户能了解保存位置和发送给 AI 的内容；密钥不进入日志与导出 | 数据流检查、日志检查、导出检查 |
| 离线行为 | 无网络时能记录与浏览已有资料；AI 能力明确说明可用条件 | 断网下编辑、保存、重开与 AI 操作 |
| 可用性 | 编辑、检索、审稿及长任务有可理解反馈；支持键盘操作和长文本 | 实际桌面交互检查 |
| 性能 | 大量日记与长文保持可用；AI 长任务不阻塞记录 | 架构阶段确定样本规模及阈值，再量测 |
| 安装与升级 | 目标系统可安装、启动、升级，数据保持可用 | 在声明支持的系统版本实际验证 |

支持系统版本、数据规模、响应时间和恢复目标尚未承诺，须在技术方案阶段设定可测标准。

## 8. 成功标准

核心验收：记录 → 保存/重开 → 审稿与练习 → 跨篇主题 → 可编辑旁白与分镜 → 导出，能在桌面软件中完成；风格档案有真实证据与用户控制；资料可以长期保存和恢复。

实际使用评估：用户是否愿意持续记录；主题是否有依据且值得创作；旁白是否接近个人表达；分镜是否足以准备拍摄；审稿是否教会用户改善文字。通过使用反馈记录结果，基线和数值目标待验证，不编造留存或增长数据。

## 9. 范围边界与未决能力

当前确定的中心是记录、写作和 Vlog 前期创作。自动剪辑/视频生成、模型训练、社交发布、支付订阅、多人协作、云同步、语音与视频理解尚未获准纳入范围，也没有判定永久排除。

视频素材管理已由用户明确排除在首次交付范围之外。生活回顾与策划导出已确认纳入，不直接连接剪辑软件。Codex 等本机 AI 工具接入已纳入，具体接口需研究。

## 10. 依赖、风险与后续决策

首要决策：目标平台、AI 接入及费用方式、数据与隐私边界、输入类型、素材与剪辑协作范围。详见 [DECISIONS.md](DECISIONS.md)。

主要风险：AI 编造事实；风格分析变成套话；源记录与项目引用失联；私密资料未经用户理解发送；生成质量难以仅靠自动测试判断。以证据、用户控制、来源关系及实际使用评审作为对应设计要求。
