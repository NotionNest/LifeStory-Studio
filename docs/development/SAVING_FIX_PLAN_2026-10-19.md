# 保存行为修正方案

日期：2026-10-19。关联 REQ-01/02、LIB-03。状态：用户已确认按方案实施；前端实现已完成，验收见文末。依据：[保存设计复核](SAVING_RESEARCH_2026-10-19.md)、[两个受控反例](CHANGE_REVIEW_2026-10-19.md)。

## 范围与目标

保留单一自动保存链路、SQLite 单连接工作线程、事务/版本/回执校验、WAL + FULL，以及重新进入编辑才固定上一轮历史的规则。本轮只处理离开边界、重试截止点与建议的保存间隔；预计涉及 3 个前端实现文件及现有关键交互测试，不改数据库结构，不增加依赖。

两项正确性修正与一项参数调整分别交付验证：前两项处理已复现的边界；800ms 是为减少短暂停顿写入的建议值，不是性能实测得出的最优值，也不是修复数据丢失的前提。

## 1. 让切换记录成为一个完整的离开操作

用户点击其他记录、新建或退出，统一经过现有 leaving 入口；失败弹窗中的“保存并继续”也走同一流程，不能保留另一路直接 execute。

顺序：

1. 同步占用离开入口，防止重复操作交叉执行。普通后台自动保存仍允许继续写作。
2. 如果中文输入法正在组合，留在旧记录等待该次组合结束，并把最终输入纳入保存；不能提前禁用编辑器截断候选文字。等待期间不启动第二次离开操作。
3. 开始真正离开时，停止旧记录接受新的修改。正文、标题、日期、标签和格式操作一起进入只读；防护同步生效，不能只依赖下一次 React 渲染。屏幕仍展示旧内容，可阅读。正常不弹出确认。
4. 调用现有 flush，等在途保存完成并提交最终编辑序号。即使离开请求开始时 dirty=false，也要在此边界确认一次。
5. 成功后读取/创建目标、处理旧草稿并进入目标编辑会话，然后替换视图；旧编辑器在所有异步等待期间保持只读。退出也只能在成功后执行。
6. 保存失败：保留旧编辑器与内容，恢复编辑能力，使用已有重试、另存、继续编辑、明确放弃流程。目标读取或进入编辑失败：同样恢复旧记录可编辑并显示错误，不丢失已经保存的内容。
7. 如目标需要恢复预览，旧编辑保持安全状态；用户取消预览时解除离开保护，恢复原编辑。恢复/丢弃操作成功后再交接到目标。正常切换与新建不得重复触发历史检查点。

实现职责：LibraryWorkspace 管理整个离开操作及目标加载；RecordEditor 管理当前输入的结束与全部编辑入口的只读状态；useRecordPersistence 继续负责 flush 和提交。需要由一个明确的离开生命周期统一释放保护，避免现有 onBusy(false) 提前解除切换保护。不得靠组件卸载时再异步保存来补救。

连续点击/快捷键沿用一个待执行意图，不并行打开多个目标；不为本轮扩建多文档后台保存服务。已有自动保存内容不会因“放弃尚未保存修改”而撤销。

## 2. 将异常重试截止点与输入防抖分开

正常输入仍使用已有 idle 与 maximum 计时器。暂忙/写入中断失败后，复用现有 retryAt 记录下次截止时刻，由单独且唯一的重试计时器负责；每个编辑器的计时器数量固定有界，不随按键累积。

- 输入可继续更新内存内容及 dirty；处于重试等待时，不能重新计算截止点，也不能启动正常保存计时器绕过退避。
- 到期调用现有串行 save。若上一次请求结果仍不确定，先重试原 requestId 和原输入；确认成功后再保存较新的输入，沿用现有回执/序号保护。
- 若到期仍处于输入法组合，保留“重试已到期”的事实，组合结束后尽快执行，不重开完整退避区间；不保存半个候选词。
- 再次暂忙按现有 1/2/4/8/16/30 秒间隔安排；上限保持 30 秒，无重试任务堆积。
- 成功后清除重试状态，尚有更新内容则回到正常调度。权限/磁盘满/损坏/未知错误/冲突不进入自动重试；校验修正仍按现有规则恢复。
- 用户主动“立即重试”或离开提交可提前尝试一次；该次完成后仅保留其对应的后续计时器，不能与自动重试重复写入。
- 结束编辑、明确放弃或卸载时清理所有调度；已发出的请求仍由既有会话/序号控制。

## 3. 保存间隔建议从 300ms 调为 800ms

建议默认停止输入 800ms 自动提交，持续输入最多 2 秒发起提交；持续输入的上限从本轮尚未保存修改开始计算，不因后续输入重置。新修改发生在在途保存期间时，仍由下一次提交追平，不误标已保存。

无修改时零周期写入，离开与 ⌘S/Ctrl+S 不等自动保存延迟。调大间隔减少短暂停顿产生的提交，但也扩大停顿后、自动提交前的异常退出输入窗口；最长触发间隔不等于磁盘提交完成时限。用户审阅前不改参数，不新增设置界面。

## 验证范围

在现有前端测试中加入或合并以下关键行为，不为每个控件重复建用例：

1. 目标读取被延迟时，旧记录已进入只读，后续修改不被接受；此前已接受的输入已保存，切换后无遗漏。
2. 保存失败或目标读取失败，旧记录保留、解除只读且可继续编辑；正常成功无确认弹窗。
3. 组合输入期间发起离开，最终文字保存后才切换；目标恢复预览取消后旧记录恢复编辑。
4. 暂忙后持续输入超过原截止点，仍按期重试；在途请求不重复、未知结果重试身份不变；组合输入结束后到期重试继续。
5. 默认参数与持续输入上限、成功后恢复正常调度、权限/冲突不自动重试，复用既有保护并按最终参数更新。

类型检查、受影响的前端集成测试和 macOS 调试包实际操作各执行一次；新增失败再扩大。此次不改变 Rust 数据行为，无需为同一前端修正重复编写 Rust 用例或重跑性能实验。远程提交后的 CI 继续遵循现有选择规则。Windows 真实界面仍需对应设备验证。

## 交付顺序与完成条件

先修离开生命周期，再独立修重试调度，最后应用经用户认可的间隔。可在同一修复分支分提交审阅，不夹带历史 UI、清理或其他模块。保护用户当前未提交文档，按现行 develop 流程工作。

完成条件：两个原反例被关键交互保护，输入法/失败返回不新增丢失，正常写作和切换无新增确认步骤，真实窗口检查通过，参数与保存说明一致。应用改动、性能结论与未验证平台分别记录，再进入 LIB-04。
