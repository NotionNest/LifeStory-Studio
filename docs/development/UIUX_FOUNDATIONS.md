| 项目 | 用户确认 |

## 2. 参考研究与取舍

用户进一步明确“我最喜欢的是 Codex 这个软件的设计和交互”。参考优先级调整为 Codex 桌面软件第一，Cloudflare 控制台与 Notion 文档工作区辅助。此前沉浸创作、面板按需收起和三种主题模式继续有效。当前已完成 [Codex 官方资料与用户三张截图的首轮分析](CODEX_UX_REFERENCE.md)，包含侧栏展开、收起与设置常规页；本机实时访问仍受限，外观选项和动态状态未验证，不把用户偏好扩大为认可其中每个控件或工作机制。参考设计语言与交互组织，不引入 Codex 的代码仓库、代理任务、终端或审批等业务体系。

本轮无法直接操作 Codex，已完成官方公开交互资料研究，并分析用户随后提供的三张界面截图。原图含项目/聊天等私人上下文，不复制进公开仓库。截图分析不冒充实时交互验证。资料查阅日期：2026-10-22。

- [Notion 侧栏说明](https://www.notion.com/help/navigate-with-the-sidebar)：内容通过侧栏组织，支持开合层级、隐藏侧栏及键盘切换。
- [Cloudflare 控制台快捷键](https://developers.cloudflare.com/changelog/post/2026-05-04-keyboard-shortcuts/)：支持导航、上下文切换、侧栏开合与深色模式切换。
- [Cloudflare 账户与站点层级](https://developers.cloudflare.com/fundamentals/concepts/accounts-and-zones/)：区分不同上下文的管理范围。

由这些交互特征及本项目需求推导的建议：借鉴 Cloudflare 对位置、对象范围和任务层级的组织；借鉴 Notion 对内容组织与侧栏开合的处理。将两者组合为“结构清楚、内容聚焦的创作工作区”。这是设计推导，尚不是用户对具体设计的确认。

不直接照搬账户/站点体系、页面无限嵌套或参考产品快捷键；本项目不因此新增账号、多工作区、块编辑能力或命令面板。颜色与精确布局需要后续参考截图和代表性设计验证，不从文档推测像素或品牌色。

## 3. 五条设计原则（草案）

1. **内容居中于任务。** 用户进入后能开始记录或继续上次创作；正文和画面是视觉主体，工具服务于当前对象。
2. **结构稳定，辅助按需。** 导航、内容列表、编辑区与辅助区职责固定；收起面板不改变内容身份，重新展开的入口始终可发现。
3. **表达来自内容。** 通过文字层级、图片和有分寸的强调表达创作感；避免用装饰、巨大空区或常驻说明取代内容。
4. **操作靠近结果。** 常用操作靠近作用对象；低频设置与危险操作分层；操作前知道影响，操作后知道结果及下一步。
5. **专注不牺牲掌控。** 保存、AI 发送范围、取消和恢复保持清楚；错误可理解、可处理，面板切换不丢输入。

## 4. 信息架构与工作区规则（草案）

- 全局导航负责日记、聊天和设置，不承载当前记录的删除、历史或格式工具。
- 日记首页列表/月历负责查找与新建，聊天侧栏负责会话切换；全局搜索统一进入 Command 菜单。共用视觉语义，不强制两种任务采用相同分栏。
- 主工作区专注当前内容；页面操作由标题栏右侧承载，先接入日记详情，正文格式与返回路径仍留在内容区。
- 辅助区用于关联来源、对照和详细属性，按需展开；不把当前主任务的唯一入口埋进多层折叠。
- 设置保留清楚的分类和返回路径，不在切换后让用户猜返回到哪里。当前采用独立设置页面，回收站为其中一个分类。
- 历史与回收站作为辅助任务，清楚显示所查看的对象及退出方式；返回后恢复原工作位置。
- 新模块沿用同一职责划分，本轮不提前显示未实现入口。

面板行为：用户主动收起/展开，有可访问名称与展开状态；收起不丢输入、选中记录或滚动位置。焦点所在面板被关闭时，焦点回到对应触发入口。窄窗口保证正文可用；已有侧栏尺寸按本地基线，右侧聊天宽度与记忆按 UX-17 规则执行，不擅自引入自动折叠。

## 5. 视觉规则（草案）

| 方面 | 规则 |
|---|---|
| 表面层级 | 深色以有区分的中性底色区分导航、内容与浮层，浅色保持同等层级；不用满屏描边、阴影或卡片堆叠制造结构 |
| 强调色 | 主操作、选中、焦点各有一致语义；成功、警告、危险单独表达；具体色相待代表性页面验证，现有绿色不自动沿用 |
| 字体 | 中文正文优先可读性与输入稳定；界面字与正文有明确层级。先使用本机系统字体，额外字体需求另行评估，不擅自安装依赖 |
| 排版 | 标题突出但不占据过量首屏；正文保持舒适行宽和行距；创建时间、标签与技术说明降低视觉层级 |
| 间距与密度 | 使用一致间距刻度；列表方便扫描，编辑区有呼吸空间；“沉浸”不意味着控件极小或将辅助文字压到难读 |
| 图标 | 沿用 Lucide，统一尺寸与描边；难懂操作有文字或提示，图标按钮有可访问名称 |
| 动效 | 仅解释面板、状态与位置变化，短且克制；尊重减少动态效果偏好，不让动效延误编辑 |

该表为制定原则；具体字号、色值、宽度与间距已在第 9 节及后续修订形成实施基线。深浅主题完整状态对照仍属验证事项，不再把全部视觉变量列为未确定。

## 6. 操作、状态与文字规则（草案）

- 每个任务区域有明确主操作；删除、彻底删除不与日常编辑操作争夺视觉重点。
- 常用入口保持可发现；完整能力保留，低频内容按需展开，避免多层折叠让操作更难找。
- 正常保存用轻量状态，不重复常驻“本地保存/自动保存”等同义说明；保存失败和冲突必须突出，保留编辑现场并提供下一步。
- AI 处理范围与当前服务可核对；生成中可以停止，未采用预览不冒充正式日记，失败不自动切换服务或模型。
- 空状态仅保留必要的空结果状态和可用操作，不加入产品介绍或鼓励性文案；已有记录但尚未选中时不得提示资料库为空。
- 清空筛选、刷新与失败重试意图分开，保留用户当前检索条件及恢复路径。
- 危险操作说明影响与恢复边界，不用大段后台运行细节压过主要任务。
- 文案围绕用户对象与动作，减少开发术语及同一层级的多套叫法；日记、聊天、预览身份不混淆。

## 7. 可访问性与验证规则（草案）

键盘可到达主要任务和面板入口，焦点可见，正文编辑不被全局快捷键截获；中文输入法组合过程不触发发送或其他破坏性动作。状态不能只靠颜色区分；深浅主题分别检查可读性、选中、禁用、错误及焦点。弹窗有清楚标题和退出方式，关闭后焦点返回合理位置。

验证覆盖典型桌面窗口及窄窗口、长标题/长文、图片与无图片、空库/有内容/无搜索结果、保存失败及 AI 中断。测试按影响选择，优先复用已有数据保护回归；不为装饰或精确 CSS 机械加测试，不由截图宣称完整可访问性合规。特殊可访问性需求尚未提供，不推定用户有或没有特殊需要。

## 9. 2026-10-22 实施授权与本轮规范

用户明确要求依据已给参考及已有信息完成页面布局、基调、侧栏、设置，并使用主流图标库；授权直接实施，不再等待额外概念图。沿用现有 React/Tailwind/shadcn，图标使用已安装的 Lucide，未引入第二套图标依赖。

本轮设计实现选择（不是逐项用户审美确认）：

- 48px 精简导航条，256px 模块列表；900px 以下列表为 208px，窗口最小验证范围沿用 760×560。由用户主动开合列表。

- 中性浅色/炭灰深色表面，少量蓝色表达主操作与焦点；颜色统一由全局语义变量管理。

## 10. UI 文案约束（2026-10-23 用户确认）

适用于 Microcopy、Helper Text、Status Text、占位符、空状态和 Tooltip。依据用户明确要求：清理冗余 UI 文案，重点删除未经明确要求的辅助说明、功能解释、统计范围说明和常驻状态提示；保留必要标题、字段标签、错误提示和操作反馈，不改变业务逻辑。

1. **默认不加解释。** 标签、控件、内容和操作本身能表达意图时，不补充“功能如何工作”“资料保存在哪里”“什么内容不在统计中”等说明。不写产品宣传、鼓励语、使用教学或实现机制介绍。
2. **保留操作所需的文字。** 页面/区域标题、字段标签、菜单及按钮名、纯图标功能的简短 Tooltip、对象身份和有决策价值的数据继续保留。不能为清爽删掉可访问名称或仅用占位符代替标签。
3. **反馈对应实际事件。** 保留保存中/已保存/未保存、加载、生成中/取消、复制或恢复结果、失败与重试等真实反馈；不添加无事件的常驻状态栏、重复说明或“尚未测试”等无动作提示。同一状态只表达一次，不引入新的定时消失或提示机制。
4. **必要后果在操作处说明。** 未保存离开、覆盖正文、恢复/彻底删除、当前服务不可用以及实际付费测试等，会影响当前选择的信息简短保留。不得扩写成全页面常驻免责声明、通用教程或后台实现说明；发送范围通过当前消息、所选资料和服务控件核对，不重复增加范围说明段落。
5. **删除就是删除。** 冗余文案不转移进 Tooltip、折叠面板、占位符或 sr-only，不换措辞重新出现。没有说明价值的统计及其范围解释一并移除；日期、标签、来源是否可用等实际内容元数据不按“冗余提示”误删。
6. **布局随之收拢。** 清理空容器、分隔线、预留高度与多余间距，列表和内容区使用释放的空间；不缩小点击区域，不改导航、表单或焦点职责，不新增页面、入口或偏好选项。
7. **保持业务契约。** 不改变保存、查询、发送范围、模型选择、采用/撤销、历史与回收规则，不删保护条件、错误处理或真实反馈。普通文案删改不新增逐字测试，复用相关行为回归；视觉由用户手动验收。
8. **新增辅助文案须有依据。** 未经明确要求，不主动添加解释性段落。必要时先指出具体用户问题，优先改进标签、操作和布局；不能用文字掩盖交互不清楚。以上限制优先于技能中的泛化“补充说明/引导”建议。
