## 行为与验收

- 后台生成不锁住消息输入；发送按钮仍可提交文本到当前聊天待发送队列，停止按钮独立保留。
- 同聊天仍仅运行一个模型任务。当前任务成功后按先后顺序发送，每条在出队时使用完整已保存历史，绝不并发穿插。
- 排队时固定聊天、请求标识、来源 ID、模型/强度、日期/时区；未投递正文可按用户要求原位修改；重试复用同一标识及参数，后端继续校验服务/资料/幂等。
- 生成失败、停止、上次中断或出队失败时暂停自动发送，由用户明确继续；结果待保存时必须先处理保存。
- 显示当前聊天待发送内容与数量，可修改或移除未处理条目；切换聊天不丢队列，也不把内容发到其他聊天。隐藏页面/预览时不启动新的队列任务，返回当前聊天继续处理。
- 队列与现有未发送草稿同属本次应用会话，退出前计入未保存提醒；不将尚未投递的内容冒充已保存消息，不新增后台/重启自动发送。
- 保留现有图片添加、模型选择、日记预览/采用及取消保护，不扩展协议或权限。

验证重点：顺序/仅成功后出队、输入草稿不被队列发送清空、停止与失败暂停、同请求重试、切换/隐藏隔离、未发送提醒、移除与中文输入法边界。

## 实施与验证

已在窗口级聊天会话的 useChatQueue 实现按聊天隔离的待发送列表，普通发送和队列投递共用现有 send IPC/日记保存保护。生成期间输入与发送可用，停止独立；请求提交等短操作期间仍保留 busy 防重。队列成功投递后不清空正在写的下一条草稿，收到任务确认后先建立运行状态再读取工作区，避免读取失败导致继续投递。取消/失败后需显式继续，队列消息可逐条移除；隐藏/离开时不调度，未投递项计入全局退出提醒。

日记生成预览保持原串行边界，不与待发送消息穿插启动；生成预览时仍可写草稿，待预览处理后再发。不改变模型目录、图片导入、SQLite 或 Rust 协议；复用后端的同会话单任务、请求幂等及来源校验。

## 待发送消息修改（2026-10-27）

用户反馈缺少修改入口，已在每条待发送消息旁增加铅笔按钮，原位多行编辑，支持保存/取消及 Escape 取消，空白内容不能保存；删除继续保留。编辑期间暂停该聊天的自动队列调度，避免上一条完成时把编辑中的旧内容发出。保存后保持原有顺序与来源/模型参数，取消恢复原正文；主输入框草稿不变，切换聊天后编辑内容仍保留。提交中的条目仍受 busy 防重保护。

失败条目修改后继续保持暂停，不自动重发；继续发送复用原请求标识，让后端对已受理但回执不确定的旧请求拒绝参数冲突，避免换新标识重复发送。未新增存储/协议/依赖，队列仍沿用现有会话生命周期。

## F-03 会话拆分（2026-10-28）

待发送状态仍由唯一窗口级会话持有，useChatQueue 负责业务动作，ChatQueue 只展示并调用编辑/保存/取消/删除动作；页面不再直接修改队列或请求 ref。新增真实 Router 回归验证视图卸载期间任务完成时不投递、返回完成权威读取后仅投递一次，并保留主输入草稿。就绪状态改为 readyChatId 驱动调度，修复仅写 ref 导致返回后队列不能可靠唤醒的问题。原有失败/停止暂停、同参数同请求重试、预览隔离及退出提醒要求不变。最终验证见 STATUS.md。

## 轮询顺序与会话隔离（2026-10-28）

轮询和手动刷新共享请求序号，较早请求的成功或失败均不能覆盖较新请求。聊天/日记上下文切换、离开后返回以及卸载会使先前代次失效，包括 A→B→A；StrictMode 清理后重新激活仍能正常刷新。当前轮询错误展示给用户，当前手动刷新错误交由业务操作处理。400ms 检查时若自动读取仍未完成则跳过该次检查，避免慢读取积压；停止轮询清理定时器并忽略在途结果，不取消模型任务。行为回归与验证范围见 STATUS.md。
