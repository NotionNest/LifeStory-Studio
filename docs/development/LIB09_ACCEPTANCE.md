## 用户实际测试顺序

使用自建合成素材，例如“LIB09 验收：今天散步十分钟，路边有一棵树”，配一张非私人图片。可以在现有资料库新增专用验收记录，不清空或覆盖已有资料。每步只需反馈通过或现象；不把点击了按钮当作对应结果已经通过。

1. 新建验收日记，输入中文并加入图片。切换后重开，再退出并重开应用：文字、日期、标签和图片保持，聊天不出现在日记列表。
2. 修改正文后查看历史；恢复一次旧版本：形成新版本，后续修改仍可找到，图片可显示。用日历/搜索/标签找到该日记。
3. 将这篇验收日记移入回收站再恢复：列表、日历和搜索一致。需要测试彻底删除时另建一次性记录，二次确认后只删该记录；不要用已有个人资料。
4. 设置里扫描 Codex，选择模型和推理强度，保存并设为默认，点击测试连接：必须实际收到模型回复才能算通过。记下 CLI 版本和所选模型，不发送密钥。
5. 新聊天发送合成讲述：收到完整回复，日记列表数量不增加。切到设置再返回，未发送输入保留；退出重开后聊天历史可继续。
6. 用该聊天生成日记预览，先返回聊天：不新增日记。再次打开/生成预览并修改后创建：只出现一篇普通日记，重试不重复创建，聊天仍独立。
7. 从这篇日记进入聊天，补充一条新事实，再预览并采用补充：只加入新段落，原文及图片保留。撤销本次采用后回到采用前内容。对已有后续修改的日记不得盲目覆盖。
8. 再发起一次生成并停止：停止后不出现完整成功结果、不自动写入日记。失败时保留原资料并显示可理解的结果；不需要反复调用模型制造故障。

API 验收使用用户实际准备使用的一家服务重复连接/首条聊天链路；其他协议的自动化结果与未联调的账户范围分开记录。Windows 按同一主链路及矩阵专项执行。无需把上述测试做成产品内“测试向导”。
