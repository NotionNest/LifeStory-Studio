# LIB-04 历史管理交付与验证

日期：2026-10-19。关联 TASK-07、REQ-01/02/12；依据已确认的资料库流程。交付分支为 feat/library-history；用户本轮已授权提交并推送，具体结果以 Git 及会话交付为准，尚未合并或发布。

## 已实现行为

- 记录编辑器可打开历史；先完成最新修改保存，失败仍保留原编辑。历史打开期间原编辑器只读，关闭后继续写作。
- 以每轮重入编辑形成的历史快照列出；使用时间/ID 游标分页。预览标题、记录日期、标签与只读富文本正文；显示重要、引用、本轮起始及恢复生成状态。
- 可标记/取消重要。用户明确确认后恢复标题、日期、标签和正文为新版本；同一事务保留恢复前内容，不修改既有引用。
- 恢复轮换编辑会话，旧自动保存不能覆盖恢复结果；请求回执支持响应丢失后以同一身份重试。结果未确认时保持只读，后续暂忙不解除保护；也可明确重新读取已保存内容，成功建立当前会话后继续。
- 普通历史创建满 90×24 小时清理；当前指针、重要标记、引用固定、来源关系和恢复草稿基版均受保护。删除对应保存/恢复回执及版本附件关联；物理图片对象生命周期仍由 LIB-05/07 实现。
- 数据库 worker 启动后及运行中每小时执行，历史列表打开时也执行。清理失败事务回滚，面板重试失败会显示错误，后台仅记录无正文失败提示。应用关闭时不执行后台清理。

Schema 6 增加恢复来源身份与恢复请求回执；迁移前保留数据库副本，失败不提交 schema。恢复来源 ID 不包含原文，也不强制永久保留无引用的源版本。

## 明确限制与剩余事项

Windows 实机与真实中文输入法候选词过程未验收；未执行签名、公证、发行、付费模型调用或压力测试。macOS 粘贴合成中文不等于真实输入法验收。

旧版历史若没有标题/日期/标签完整快照，只提供正文预览，禁止用当前字段拼造历史后恢复。待处理恢复草稿保留到用户明确选择，不按普通历史到期丢弃。

迁移前数据库备份属于独立升级恢复资料。用户询问“迁移是什么、为何需要”，已解释；备份保留期限仍未确认，本次不删除。因此普通历史清理不承诺清除迁移备份、外部导出或完整备份中的副本；LIB-07 彻底删除仍须覆盖应用管理来源副本。
