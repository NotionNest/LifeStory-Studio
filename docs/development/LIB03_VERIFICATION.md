# LIB-03：自动保存与恢复草稿

日期：2026-10-16。关联 REQ-01/02、TASK-07、LIB-03。实现与自动化验证完成，桌面及远程验证结果在下方记录。

## 保存行为

停止输入 1 秒后自动保存；持续输入最长 5 秒发起一次保存。按钮和 ⌘S/Ctrl+S 可立即保存。正文、标题、日期与标签共用编辑序号；中文组合输入期间暂停写入，组合结束后继续。较旧保存回执不能把较新编辑标为已保存。

本地恢复草稿独立于正式内容：停止输入 300 毫秒、持续输入最多 2 秒发起快照写入，使用真实 SQLite 事务提交。正式保存成功只清理该保存序号及以前的草稿，不清理更新内容。实际完成时刻受磁盘速度影响，尚未写入磁盘的最后输入无法保证找回。

正式保存失败即暂停自动保存，保留编辑现场并提供手动重试、主动另存和继续编辑；明确放弃后才清理。恢复草稿写入失败同样明确提示并暂停自动流程，不自动改换目录。手动保存成功后恢复自动保存。

## 重开与恢复

启动读取待处理草稿，展示最近一份的正式内容/草稿对照，其余可从列表进入。预览标题、日期、正文和标签，选择恢复、稍后处理或丢弃。没有用户选择不覆盖正式内容。恢复操作原子地建立新编辑会话并保留恢复副本，正式保存成功后才清理；正式内容有更新时预览明确提醒。

编辑会话由数据库发放，旧会话的迟到保存/草稿请求被拒绝；同会话低序号草稿被忽略。放弃修改会结束会话，阻止在途请求重新生成已丢弃草稿。schema 3 增加会话表，迁移前沿用一致性快照保护。

恢复草稿与迁移快照包含原始资料，保存在受管理的本地目录，不上传。历史/回收清理（LIB-04/07）必须包含草稿、保存回执和迁移快照的保留规则，不能仅删除当前记录后就声称原文已彻底清理。当前不提供完整备份恢复或加密承诺。
