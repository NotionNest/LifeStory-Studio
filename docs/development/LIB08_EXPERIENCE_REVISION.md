## 1. 用户明确的新方向

- 有统一聊天入口，配置服务后可以直接聊天；聊天形成独立历史，不混入真实日记列表。
- 重新设计聊天创建日记、聊天补全现有日记的流程，降低复杂度。
- 聊天界面使用成熟的 shadcn AI Elements。
- AI 服务配置放到软件设置；新增独立设置页面。

这些方向取代此前将文字、对话、整理稿混排为一份资料列表的呈现。用户随后明确同意本页方案，以下交互作为本轮实施依据。

## 2. 原实现的问题

当前 `records.kind` 同时承载 text/conversation/draft，日常查询、日历数量和搜索默认混合三种；AI 整理完成就自动创建 draft。上一轮只拆按钮，没有修正信息架构和生成即入库的行为。

“独立稿件”原本用于不覆盖原文，这个保护仍有价值；但不必因此增加第三种用户必须理解的记录类型。建议取消用户可见的“整理稿”类别：生成期间是待采用内容，确认后就是普通日记。

## 3. 三个主入口

| 入口 | 页面 | 核心动作 |
|---|---|---|
| 日记 | 日记列表/日历 + 编辑器 | 写日记、打开日记；按需“聊聊这篇日记” |
| 聊天 | 独立会话列表 + 消息区 + 底部输入框 | 新对话、继续聊天；按需“保存为日记” |
| 设置 | 设置导航 + AI 服务配置 | 添加/测试服务、选择默认服务和模型 |

聊天是主页面，不再覆盖资料库的大弹层。不同时常驻选材、来源、任务面板。来源与关联保留在详情中，日记列表不显示聊天，也不增加“整理稿”筛选。

## 4. 直接聊天

设置服务并选为默认 → 打开聊天 → 输入并发送。首次发送事务创建会话和用户消息，不先要求“新建空白对话”。进入空白页不产生空记录、不调用模型。左侧会话历史按最近活动排列；标题取首条讲述，支持重命名、搜索、删除及恢复。

输入框附近显示当前服务/模型并可主动切换。默认配置用于新会话；既有会话保留所选目标，不因修改全局默认而静默切换。未配置时给“前往设置”入口，不把整张配置表放进聊天。返回设置前后的输入与阅读位置保留。

普通聊天不读取日记。需要使用某篇日记时，用户主动附加为上下文；输入区显示可移除的日记标题标记。每次请求固定实际使用的版本；删除来源、取消、超限和晚到结果仍沿用数据保护。

## 5. 从聊天创建日记

聊天 → “保存为日记” → 可编辑的日记预览 → “创建日记”。

- 默认使用当前会话已发送的文字；额外资料按需添加，不默认读取整库。
- 生成预览前明确该范围，模型不能把 AI 的猜测和追问当作用户经历。已有未发送输入保留，并明确不纳入本次整理。
- 预览只展示标题、日期、正文与创建动作；用户可以改字、调整日期、重新生成或返回聊天。
- 只有“创建日记”成功才出现普通日记；预览和失败任务不进入日记列表。生成结果本地保存以便重开，属于任务结果，不是第三种正式记录。
- 创建操作幂等。成功后显示“已创建日记 · 打开”，不因重试重复入库。继续聊天不会自动改写该日记。
- 再次采用同一会话内容时明确“更新已关联日记”或“另建一篇”，不静默决定，不一日一篇强合并。

## 6. 通过聊天补全已有日记

日记编辑器“聊聊这篇日记” → 同一个聊天空间，明确显示关联的日记 → 补充讲述 → “补充到这篇日记” → 预览新增段落和插入位置 → “加入日记”。

建议默认只整理新增讲述为补充段落，放在文末；采用前可编辑。不得整篇重写原文、重复插入原有内容或凭空补经历。连续补充记录已采用的消息范围，避免上一段重复进入日记。

如果用户明确想整体重组，作为按需的“重新整理全文”，先展示修改前后，再由用户选择采用；不把重写作为默认补全方式。全文替换必须保留当时版本与图片，不让纯文字输出丢失正文图片。

预览绑定目标日记版本。期间用户改了日记则阻止盲目采用，保留建议和新原文，提示重新核对；采用成功通过正常编辑器链路持久化，支持撤销和历史。日记被删除时禁止采用，保留独立聊天身份并标记关联失效。

## 7. 设置页

本轮只提供真实可用的“AI 服务”设置，不放无功能的账号、同步等占位项目。

- 已配置服务列表：名称、模型、默认标记、可用性测试时间、编辑/停用。
- 添加或编辑：先选服务，填模型与凭据；地址、协议、预算等放高级配置，仍可核对实际目的地。
- 默认服务/模型：保存到本机偏好，用于新会话；停用默认服务后要求主动选择，不自动使用其他服务。
- 连接测试单独点击，展示合成请求及可能计费；保存配置本身不调用模型。
- 凭据仍仅写本机私有凭据目录，不读回前端；目的地变更不自动复用旧密钥。设置页离开保护未保存字段，隐藏与重开不清空用户输入。

## 8. AI Elements 接入调研

2026-10-21 读取官方文档，并按项目要求执行 ctx7 library → docs（/vercel/ai-elements）。Context7 的 Vercel 资料包含旧版接口，当前迁移状态以 shadcn 官方页面为准。

- [shadcn AI Elements](https://ui.shadcn.com/docs/ai-elements)：当前以可复制的组合模式提供；旧 AI SDK Elements 项目正在迁入 shadcn。新工作采用当前官方组合，不整套引入旧 Next.js 聊天模板。
- [Chat](https://ui.shadcn.com/docs/ai-elements/radix/chat)：Message Scroller、Message、Bubble 和 Input Group 组合；匹配项目既有 Radix 配置。
- [Prompt Input](https://ui.shadcn.com/docs/ai-elements/radix/prompt-input)：输入区、附件、模型选择与发送控件。只引入本项目使用的部分。
- 这些界面不要求改成云端应用。保留 Rust 协议适配、凭据和任务生命周期，经现有有限 IPC 驱动受控组件；不引入 AI Gateway、遥测或前端密钥。
- 引入组件时验证流式滚动、中文组合输入、键盘发送、停止、失败重试、图片只在本机保存。模型 Markdown 渲染需限制远程图片/不安全链接，不能因换组件自动外发内容。

2026-10-22 已通过 shadcn 官方 CLI 安装 Radix 消息、滚动、输入和必要设置控件并接入；原按钮未覆盖，保留 Rust IPC 与凭据边界。实际桌面链路验证见交付记录，不把组件示例当作真实模型联调。

## 9. 产品依据及取舍

[Day One Daily Chat](https://dayoneapp.com/features/daily-chat/) 展示聊天后生成、审阅、编辑并保存为日记；[使用指南](https://dayoneapp.com/guides/ai-features/daily-chat/) 也说明可继续聊天再更新日记。借鉴主动成文，不照搬它的每日会话、记忆、云服务或订阅规则。

[Day One Go Deeper](https://dayoneapp.com/guides/ai-features/go-deeper/) 从已有日记内容出发帮助继续书写；[Notion AI](https://www.notion.com/help/notion-ai-faqs) 的文字建议可接受或丢弃。由此提出本项目“预览 → 明确采用”的建议，不宣称这些产品证明了本方案已经过用户验证。

## 10. 数据与实施影响

不是仅做前端隐藏筛选。聊天的查询、搜索、分页、日期计数、回收站、图片所属及来源接口都要按内容领域隔离；共享数据库允许复用基础设施，但 API 必须保证日记空间不会泄漏聊天条目。

待采用结果属于生成任务；采用事务创建/更新正式日记并记录消息范围与目标版本。兼容已有 text/conversation/draft：聊天迁入聊天历史，既有可编辑稿件作为普通日记保留，来源和身份不丢失；不得为取消类别删除旧内容。此前已经生成的稿件不能自动降为未保存内容。具体迁移和接口在实施计划中细化并有真实 SQLite 回归。

实施顺序：确认本页交互 → 应用导航/设置与默认服务 → 独立聊天领域及 AI Elements → 创建日记预览/采用 → 补全日记预览/采用 → 旧数据迁移与回归/实际窗口验收。每项都是完整流程的一部分，不用局部设置页冒充本轮整体重设计已完成。

关键验收：直接聊天不新增日记；取消预览不新增日记；创建仅一次；补充仅写用户采用的内容；版本冲突不覆盖新编辑；聊天与日记各自搜索/删除/恢复；服务配置返回不丢输入；已有稿件与聊天升级后仍可打开。真实服务与 Windows 限制继续单独记录。
