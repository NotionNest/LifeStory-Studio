## 统一模型入口调研（2026-10-26）

用户反馈：不应先选服务才能查看模型，希望所有可选模型统一可选。本节记录方向修订与调研建议；现有三控件实现尚未修改，细节未标为用户确认。

官方依据：
- [Open WebUI 连接与模型选择](https://docs.openwebui.com/getting-started/quick-start/connect-a-provider/starting-with-openai/)：连接保存后从模型选择器使用模型；不同连接同名模型通过来源前缀区分。Context7 `/open-webui/docs` 同步核对该规则。
- [Cherry Studio 服务配置](https://www.cherryai.com/docs/en/pre-basic/providers/)：设置负责连接信息、同步模型及连接检查，模型仍依赖已配置连接。

建议：输入区改为统一可搜索模型菜单，汇总所有已启用且已接入聊天能力的 CLI/API 模型；模型名称为主、配置名称为来源副标。选择一条记录同时确定 profileId 与 model，随后显示该条目的实际推理强度。默认选择沿用设置，聊天覆盖不回写默认。相同模型不同连接保留独立条目，键为 profileId+model，不静默合并或自动路由。

各来源独立异步读取与失败重试；某一来源失败不阻塞其他目录。目录可见不等同账户实际调用成功，不能标成已验证。未配置服务、未接入生成协议的 CLI、非聊天模型不因统一入口变为可调用；需按协议能力识别，不能用名称猜测。未实现 API 强度仍不展示假能力。不增加全球静态模型目录、自动切换、连接权限或依赖。

后续实施可复用现有 profileId/selection 及逐任务快照，主要调整前端目录汇总、搜索选择及联动测试；无需为统一入口重写后端服务路由。

## 统一模型入口实施

用户已明确授权实施上述调研建议。已移除独立服务选择器，以现有 Command + Popover 组成统一可搜索模型菜单；搜索模型名称、显示名及配置来源。每条选项同时携带服务身份与模型，同名跨来源保留独立项、展示来源并标记当前项；不自动路由。选择后联动既有模型能力强度，并关闭菜单回到触发器。保持已保存自定义模型/当前会话模型可见，目录读取失败不自动更换选择。

目录并发按已启用配置读取，来源分别反馈读取失败并单独重试，失败不阻止其他来源选择；离页/配置变化丢弃迟到结果。保留服务+模型运行时选择、草稿恢复与后端快照协议，无新依赖/后端改动。API 继续使用现有目录接口，目录返回不等于账户联调或聊天能力已验证，不新增能力猜测。

最终构建及受影响前端三文件 28 项通过，覆盖统一来源、同名模型不合并、搜索筛选、模型/强度联动、仅失败来源重试、迟到结果、草稿恢复与发送配置。单轮设计检查无发现，未忽略规则。视觉、键盘原生交互与真实模型未代验证；既有生产大包警告保留。
