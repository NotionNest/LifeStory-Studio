## 1. 用户已明确的行为

- 设置独立展示；“模型与提供商”下有“本机 CLI / API 提供商”。
- 扫描/重新扫描本机 CLI，得到已安装的 CLI 列表。
- 点击 CLI 条目手风琴展开，在条目内部配置；不再使用列表外的通用添加表单配置本机 CLI。
- 模型目录由 CLI 动态获取，用户直接选择；同时支持沿用 CLI 当前配置和显式自定义模型 ID。
- 参考图用于交互逻辑，不照搬样式，沿用项目语义主题和 shadcn 控件。
- 先打通 Codex；实际窗口操作由用户完成，不控制鼠标。

以下是为这些要求补齐的产品建议，尤其其他 CLI 的范围，不把截图中的所有产品自动视为已要求完整接入。

## 2. 推荐的完整操作

进入本机 CLI → 扫描 → 查看检测列表 → 展开一个 CLI → 读取其模型及配置 → 选择跟随/指定/自定义模型 → 选择支持的推理强度 → 保存配置 → 显式测试 → 设为新聊天默认。

扫描与展开都不发送模型消息；测试才发送界面说明的合成文字。模型目录可能由 CLI 请求服务或读取自身缓存，界面使用“从 CLI 获取 · 更新时间”，不能保证它每次都绕过 CLI 缓存直连服务。目录有某模型也不等于当前账户一定能调用。

### 列表与手风琴

顶部显示“已检测到 N 个 CLI”和扫描/重新扫描。未扫描、扫描中、扫描完成为空、部分失败与扫描失败分别展示。

每种 CLI 一个条目，折叠行只显示名称、所选安装版本、简明状态、展开按钮。多安装位置放在条目内的“安装位置”选择器，不能悄悄优先使用新版本或另一份 CLI；新扫描结果不能改变既有选择。

展开后按次序显示：

1. 当前安装路径和版本；多安装可切换，非标准位置可主动指定可执行文件。
2. 连接/登录状态及当前有效模型（无法核实时显示未知，不推断已登录）。
3. 模型选择器及“刷新模型列表”，可搜索，展示真实名称和 ID。
4. 仅当 CLI/模型支持时显示推理强度或思考模式。
5. 保存、测试连接、设为默认及停用已保存配置；在当前条目中显示结果。
6. 高级项保留上下文与输出预算，普通操作不要求填写。

同一时刻展开一个条目；未保存修改时不直接切换安装、折叠、重扫或离开分类而丢失输入，应保留编辑并提供保存/放弃选择。全局退出保护沿用现有规则。

保存之前可读取模型目录；检测到 CLI 不自动保存配置、设默认或发送测试。已有配置重开应直接显示在其 CLI 条目内，不再重复出现一份“已配置服务”列表与另一份编辑表单。

### 三种模型选法

| 选择 | 行为 |
|---|---|
| 跟随 CLI 设置 | 新建应用会话时不主动指定模型，读取 CLI 在该应用运行上下文中的有效配置并显示可核实的模型；不是目录中的推荐默认项，也不是终端中另一个活动会话的临时选择 |
| 从 CLI 模型目录选择 | 保存明确模型 ID；发送时固定使用，不因为目录刷新或默认值变化而改选 |
| 自定义模型 ID | 用户主动选此项才显示文本框；标为自定义、未验证，不伪装成 CLI 返回的目录模型 |

“跟随 CLI 设置”是明确选择的模式，不是读取失败后的兜底。无法读取目录时显示具体错误与重试；不伪造列表或自动改成自定义。无法确认实际模型时可以保留跟随偏好，但不能声称已核实；生成仍须满足权限隔离及模型身份检查。

跟随模式在创建新应用聊天时解析并固定；已有聊天保留模型与推理配置，避免用户在终端改默认后旧聊天悄悄换模型。界面同时展示“偏好：跟随 CLI”与“本次聊天实际模型”。若希望已有聊天更新，必须明确操作。任务持久记录实际模型、CLI 安装身份/版本和推理强度，不能只存会变化的偏好。

### 推理强度

来自所选模型或 CLI 协议的能力描述，不全局写死 Low/Medium/High。允许“跟随 CLI”；明确指定时只发送支持的值。更换模型后重新核对原强度，不兼容时要求重新选择，不静默改值。CLI 未报告能力时不展示虚构选项；不同 CLI 的 thinking 开关不能直接伪装为同一组 reasoning effort。

## 3. 官方能力与接入差异

| CLI | 官方依据/已核实事实 | 本项目建议 |
|---|---|---|
| Codex | App Server 的 model/list 返回模型、显示名、能力、推理强度及推荐默认标记；config/read 返回分层后的有效配置。目录有分页。 | 优先完成；目录、配置读取和生成分别核验协议，保留完整元数据，不再压成 string[]。不使用 isDefault 冒充用户的配置模型。 |
| Kimi | 官方 kimi acp 通过 stdio JSON-RPC；session/new 返回 configOptions，session/set_config_option 管理模型/思考模式。 | 可作为后续原生 ACP 接入候选；按返回配置渲染，不抄 Codex 参数。目录探测若需新建会话须在隔离目录关闭并回收，不读旧聊天。 |
| Cursor Agent | 官方 agent acp 支持 stdio 集成，--list-models 可列模型。 | 接入候选；需要验证当前安装版的结构化配置、模型选择及工具隔离，不能因为找到了 agent 可执行文件就认定为 Cursor。 |
| Claude Code | 官方 /model 和配置覆盖有明确语义；SDK 的模型控制能力还需固定版本验证。未在本轮完成可读取的官方 SDK 页面与本机协议核验。 | 列为研究候选；不抓终端菜单、不用 Anthropic API 目录冒充 Claude CLI 模型目录，不自动安装第三方 ACP 桥接。 |
| Gemini CLI | 官方配置说明 ACP 启动及会话覆盖参数。 | 列为研究候选；实际目录/配置能力和无工具权限仍需核实，不能把 ACP 名称相同当成所有能力相同。 |

推荐按白名单识别这些主流 CLI，实际生成按各适配器通过的能力开放。具体其他 CLI 交付范围尚待确定；本轮优先 Codex 的要求不变。不能把“发现已安装”和“支持本项目聊天”混为同一状态。

对于 ACP，优先使用版本协商后返回的 configOptions/currentValue/options，并处理配置更新通知。较早版本若只报告旧字段，必须有明确测试的版本适配，不静默猜测。ACP 规范本身不能证明某个产品已经实现全部字段，也不能证明代理进程没有自身工具或文件权限。

## 4. Codex 0.146.0：需要纠正的限制

本机 codex-cli 0.146.0 本轮成功执行 generate-json-schema（输出仅存 /tmp，不含账户或日记）。其 schema 已有：

- ModelListParams：cursor、includeHidden、limit；ModelListResponse：data、nextCursor。
- Model：model、displayName、isDefault、supportedReasoningEfforts、defaultReasoningEffort 等。
- ConfigReadResponse：config/layers/origins；有效配置包含 model 和 model_reasoning_effort。
- TurnStartParams：effort；模型可以在协议层指定。

因此上一轮把“目录读取”也一并限制为 0.163.0，范围过宽。应拆成发现/目录/配置/生成能力分别判断。schema 存在只证明本地安装版公开这些协议字段，不代表登录、实时目录调用或真实生成已通过。

现有 0.163.0 生成锁来自其已核对的无工具、无额外上下文与临时请求契约。不能直接删锁或只把 read-only 当作禁止读取。0.146.0 的真实生成需要另外核实隔离能力；这一项仍未验证。后续使用版本加能力契约测试来维护支持范围，未知版本显示具体受限项，不自动升级。

## 5. 实现边界

### 扫描与身份

Rust 扫描 PATH、已知安装位置和用户明确指定位置；macOS 包含 Homebrew、常见用户 bin、nvm；Windows 检查 PATH/PATHEXT 及真实安装方式。用固定产品探测命令核实身份，不运行任意扫描结果或用户 shell 初始化脚本。别名/函数不冒充独立可执行文件。

解析真实路径并去重同一安装；多个实际版本仍供选择。Node 包装脚本必须核实其运行时定位，避免 Finder 启动缺少终端 PATH 时报告“未安装”。单项失败不清空其他扫描结果，各项限时、限输出、限并发，并回收子进程。重扫不删除已保存配置；路径消失标记不可用。

### 状态与异步

分别记录 installed、protocol、authentication、catalog、generationCheck；“检测通过”不等于“连接测试通过”。单项错误留在所属卡片；测试显示进行中，可取消，取消后清理进程，晚到结果不能修改其他卡片或覆盖新配置。

展开时按需获取目录与白名单有效配置；手动刷新真实重新查询 CLI。保留时间、路径、版本和结果来源；旧结果标记过期，不称为当前检测成功。新扫描或切换安装后丢弃旧安装元数据，保留用户编辑并明确提示重新核验。

### 数据与安全

前端只接收名称、版本、路径、模型能力及最小状态，不返回整个 config、凭据、账号详情或 token。有效配置即使通过 RPC 读取，也只在 Rust 提取白名单字段，不进入日志或持久快照。保存只写本应用，不更改用户 CLI 全局默认、登录、配置文件或其他客户端。

复用现有 Rust 任务协调、取消、幂等和来源保护。跟随模型需要在启动任务前解析并固化，不能在生成途中改变；解析失败不写入伪成功任务或再次付费重试。已有固定模型配置升级后仍保持固定语义，不自动转为跟随。

本轮不新增“失败时换 CLI/API”能力。其他 CLI 即使有自己的自动模型切换，也必须明确识别其行为；无法保证用户指定模型时不宣称固定模型执行成功。

## 6. 需要改到的位置与验收

- 前端新增专门的本机 CLI 列表/条目组件；AiSettings 负责分类，API 表单继续复用，避免把分支继续堆进同一个表单。
- aiApi 与 Rust IPC 从 Codex 路径/string[] 扩展为安装身份、目录详情、当前有效配置与探测状态；对应 commands、注册、权限及测试夹具同步。
- Profile 区分跟随/指定/自定义和推理选择；任务/会话保存本次解析结果。根据实际持久数据变更制定兼容迁移与真实 SQLite 回归，不能只靠前端隐藏。
- Codex 适配拆开探测兼容与生成隔离验证，逐页读取目录；自定义输入在前后端校验，真正发请求时检查实际使用模型。
- 测试覆盖：空列表/多安装/部分失败、重扫保留编辑和已存配置、手风琴键盘及保存保护、动态目录/分页/过期、三种模型语义、模型与强度依赖、CLI 默认变更不影响旧聊天、取消与晚到、旧配置保留及无凭据透出。
- 用户完成实际 Codex 测试：扫描 → 展开 → 读目录 → 跟随或选模型 → 设推理强度 → 保存 → 显式测试 → 新聊天；目录/配置失败能恢复，旧聊天模型不变。按用户要求不做鼠标验收。

交付标准是这条完整链路，不是仅做手风琴外观，也不是展示一份静态模型表。

### 扫描与测试入口修正

用户实际反馈后，扫描限定默认独立 CLI：保持 PATH 优先级，不执行其他应用包内部组件；其他安装只列出路径，不在扫描中自动运行。安装来源不再由用户选择，使用 PATH 当前默认独立 CLI，不自动改用较新的其他安装。统一测试无需先保存，先握手再按生成隔离要求验证模型，分别报告阶段结果。目录查询明确展示数量及空列表状态，不能以读到当前模型代替目录成功。安全拦截的实际文件/原因尚未定论，应用不绕过系统检查。

### 设置交互收敛（2026-10-22）

按用户最新要求，删除安装来源选择、配置名称和独立模型搜索框；配置名称在内部维护，既有记录保留。模型与推理强度并排展示，目录刷新靠近模型控件；推理选项来自当前模型实际能力，未报告时显示禁用及原因，不编造选项。路径、版本、目录时间和预算放入高级设置与诊断。

只保留一个“测试连接”入口，可测试未保存设置，不自动保存或改变聊天默认。先检查 CLI 通信，再验证所选模型；取消绑定同一请求。旧版本未验证生成时只报告 CLI 通信成功。测试会显式发送合成文字并可能消耗额度。

LIB-08 的交付包含设置页完整交互、反馈与保存保护；不是先交付功能再等待后续任务修补 UI。LIB-09 负责跨平台整体验收与文档同步，不能代替 LIB-08 自身的交付标准。实际窗口由用户测试，本轮不控制鼠标。

### 0.146.0 实际使用阻断修正（2026-10-22）

用户反馈当前 CLI 可读目录但不能测试/聊天。根因是测试、生成、扫描能力标记与检查入口分别写死 0.163.0。核对官方 rust-v0.146.0 源码后，确认 thread/start 支持空 environments、空 runtimeWorkspaceRoots、禁用自动模型替换及临时线程；工具计划在无环境时不注册命令、文件修改、图片读取和权限工具。保留现有启动/线程扩展禁用、MCP 禁用、响应权限核验和取消保护，将共同兼容判断扩展到已核对的 0.146.0 与 0.163.0，不自动升级或切换安装。未知版本仍明确报告未发送模型请求。此规则取代本文件较早“生成仅限 0.163.0”的描述。

官方版本证据：[ThreadStartParams](https://github.com/openai/codex/blob/rust-v0.146.0/codex-rs/app-server-protocol/src/protocol/v2/thread.rs)、[工具构建](https://github.com/openai/codex/blob/rust-v0.146.0/codex-rs/core/src/tools/spec_plan.rs)、[空环境工具测试](https://github.com/openai/codex/blob/rust-v0.146.0/codex-rs/core/src/tools/spec_plan_tests.rs)。本轮使用 Context7 获取协议参考，再按版本源码确认行为；未执行真实 CLI 或读取凭据。

配置保存仍生成新配置 ID 并保留旧配置快照。尚未发送的新聊天若持有被此次保存替换的旧默认 ID，随默认配置更新并保留输入；已有聊天和用户手动选择的其他服务不自动更换。
